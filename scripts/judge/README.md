# 심사 계정 표본 채우기

공모전 심사 계정에 **저장 동선·찜한 대회·저장 코스**를 채운다. 이슈 #293(#225 BLOCKER 8).

## 왜 필요한가

심사위원이 받는 것은 계정 하나다. 그 계정이 비어 있으면 **로그인해야 보이는 화면이 전부 빈 상태**로 보인다.

```
마이 > 동선          저장한 동선이 없어요
마이 > 저장 코스      저장한 코스가 없어요
마이 > 찜한 대회      찜한 대회가 없어요
```

세 화면 모두 P0 기능인데, 빈 화면은 "안 만든 것" 과 구분되지 않는다. **표본을 미리 채워야 한다.**

## 하는 일과 안 하는 일

| | |
|---|---|
| **한다** | 이미 있는 계정으로 로그인 → 찜 3건 · 저장 코스 3건 · 저장 동선 1건 채우기 → 되읽어 확인 |
| **안 한다** | 계정 생성. 가입은 이메일 인증 코드가 있어야 해서(§1-1) 사람이 앱이나 콘솔에서 만든다 |

## 준비

`scripts/.env` 에 세 값을 넣는다. **`.env` 는 gitignore 대상이고 저장소에 올리지 않는다**(AGENTS 8장).

```bash
RUNNINGGU_API_BASE_URL=https://staging-api.runninggu.store
RUNNINGGU_JUDGE_EMAIL=
RUNNINGGU_JUDGE_PASSWORD=
```

## 실행

```bash
cd scripts/judge
set -a; source ../.env; set +a

python seed_judge_account.py --dry-run          # 로그인과 고르기까지만, 쓰기 없음
python seed_judge_account.py --out summary.json # 실제로 채운다
```

요약은 이렇게 나온다. **이메일은 가려서 찍는다** — 이 JSON 을 이슈나 PR 에 붙일 수 있어야 해서다.

```json
{
  "account": "ru***@example.com",
  "contestIds": [11, 13, 14],
  "favorites": [11, 13, 14],
  "savedCourseIds": [77, 78, 79],
  "itineraryId": 42,
  "verified": { "favoriteCount": 3, "savedCourseCount": 3, "itineraryCount": 1 },
  "warnings": []
}
```

`verified` 는 **채운 뒤 목록으로 되읽은 값**이다. 쓰기가 `200` 을 준 것과 화면에 보이는 것은 다른 말이라 따로 확인한다.

## 몇 번을 돌려도 같다

`scripts/` 규칙대로 2회 실행해 결과가 같아야 한다(AGENTS 3장). 세 가지가 전부 멱등이라 그렇게 된다.

```
찜        PUT /me/favorites/{id}    이미 찜한 것을 다시 눌러도 그대로
저장 코스  POST /me/courses          geometry 가 같으면 기존 id 를 돌려준다
저장 동선  POST /itineraries         같은 (대회, 시작일, 종료일) 이면 교체한다
```

동선 **내용**은 외부 POI 조회 결과라 실행마다 조금 다를 수 있다. 개수는 1건으로 고정된다.

## 고르는 규칙

임의로 정하지 않고 이유가 있다.

- **찜할 대회** — 목록 앞에서 3건. 단 **좌표가 없는 대회는 건너뛴다.** 찜은 되는데 그 대회에서 동선을 만들면 `409 CONTEST_LOCATION_UNAVAILABLE` 이라(§5-1), 심사위원이 위저드를 눌렀을 때 오류만 본다
- **저장할 코스** — `GET /courses/near` 의 `ROUTE` 중 가까운 것부터 3건. **걷기 스팟(`SPOT`)은 저장 대상이 아니다** — 코스가 아니다
- **동선 기간** — 대회 전날 ~ 대회 당일(1박 2일). 대회일을 반드시 포함해야 하고(§5-1), 당일치기면 회복일 블록이 안 나와서 §5.6 의 특징이 화면에 안 드러난다
- **테마** — `TOUR` · `FOOD`. §4.8 의 "1개 이상" 을 채우는 최소 조합이다

## 저장 코스가 모자랄 때

출발지가 **서울시청**이라 `ROUTE` 가 3건이 안 나올 수 있다. 수도권에는 두루누비 코스가 사실상 없기 때문이다(AGENTS 6장 — 반경 8km 안 0건).

그 경우 경고로 남긴다. 조용히 넘기면 저장 코스 화면이 왜 비었는지 아무도 모른다.

```
경고: 저장할 ROUTE 가 0건뿐이다 — 출발지를 바꾸거나 코스 동기화를 확인한다
```

`COURSE_ORIGIN` 을 두루누비 코스가 있는 지역으로 바꾸거나, OSM 생성 경로가 뜨는지 확인한다.

## 이 스크립트로 끝나지 않는 것

#293 의 남은 칸이다. 표본을 채우는 것은 그중 하나다.

- [ ] 공모전 요강의 **심사 계정 제출 형식** 확인
- [ ] 전용 계정 생성 (이메일 인증 필요 — 사람이 한다)
- [x] 저장 동선·찜·저장 코스 표본 채우기 ← 이 스크립트
- [ ] 로그인 필요한 화면 전부 접근되는지 **기기에서** 확인
- [ ] 새 기기에 설치본을 올려 처음부터 밟기
- [ ] 계정 정보를 제출 자료 형태로 정리 (**비밀번호는 저장소에 커밋하지 않는다**)
