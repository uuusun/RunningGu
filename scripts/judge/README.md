# 심사 계정 표본 채우기

공모전 심사 계정에 **저장 동선·찜한 대회·저장 코스**를 채운다. 이슈 #293(#225 BLOCKER 8).

## 왜 필요한가

심사위원이 받는 것은 계정 하나다. 그 계정이 비어 있으면 **로그인해야 보이는 화면이 전부 빈 상태**로 보인다.

```
마이 > 동선          저장한 동선이 없어요
마이 > 저장 코스      저장한 코스가 없어요
마이 > 찜한 대회      찜한 대회가 없어요
```

세 화면 모두 P0 기능인데, 빈 화면은 "안 만든 것" 과 구분되지 않는다. **표본을 미리 채워야 한다.**

## 하는 일과 안 하는 일

| | |
|---|---|
| **한다** | 이미 있는 계정으로 로그인 → 찜 3건 · 저장 코스 3건 · 저장 동선 1건 채우기 → **저장한 id 를 되읽어 대조** |
| **안 한다** | 계정 생성. 가입은 이메일 인증 코드가 있어야 해서(§1-1) 사람이 앱이나 콘솔에서 만든다 |

## 준비

`scripts/.env` 에 세 값을 넣는다. **`.env` 는 gitignore 대상이고 저장소에 올리지 않는다**(AGENTS 8장).

```bash
RUNNINGGU_API_BASE_URL=https://staging-api.runninggu.store
RUNNINGGU_JUDGE_EMAIL=
RUNNINGGU_JUDGE_PASSWORD=
```

## 실행

```bash
cd scripts/judge
set -a; source ../.env; set +a

python seed_judge_account.py --dry-run          # 표본 저장 안 함 (로그인·조회는 실제로 보낸다)
python seed_judge_account.py --out summary.json # 실제로 채운다
```

요약은 이렇게 나온다. **이메일은 가려서 찍는다** — 이 JSON 을 이슈나 PR 에 붙일 수 있어야 해서다.

```json
{
  "account": "ru***@example.com",
  "contestIds": [11, 13, 14],
  "favorites": [11, 13, 14],
  "savedCourseIds": [77, 78, 79],
  "itineraryId": 42,
  "verified": {
    "ok": true,
    "favorites":    { "saved": 3, "unique": 3, "confirmed": 3, "listed": 3,
                      "duplicated": [], "missing": [], "shortfall": 0 },
    "savedCourses": { "saved": 3, "unique": 3, "confirmed": 3, "listed": 3,
                      "duplicated": [], "missing": [], "shortfall": 0 },
    "itineraries":  { "saved": 1, "unique": 1, "confirmed": 1, "listed": 1,
                      "duplicated": [], "missing": [], "shortfall": 0 }
  },
  "warnings": []
}
```

### `verified` 는 개수가 아니라 id 를 대조한다

쓰기가 `200` 을 준 것과 화면에 보이는 것은 다른 말이라 되읽어 확인한다. 그런데 **개수만 세면 그 "다른 말" 을 못 잡는다** — 무관한 id 가 같은 수만큼 와도 통과하고, 같은 id 를 두 번 저장해도 "2건" 으로 보인다(#305 리뷰). 그래서 이번에 저장한 **고유 id** 를 되읽은 목록과 맞춰 보고, 어긋난 이유를 셋으로 나눠 적는다.

| | 무슨 일인가 | 할 일 |
|---|---|---|
| `missing` | 저장했다는데 목록에 없다 | 쓰기가 실제로 안 먹혔다 — 서버를 본다 |
| `duplicated` | 같은 id 를 두 번 저장했다 | 표본 개수가 그만큼 준다 — 고르는 규칙을 본다 |
| `shortfall` | 확인된 고유 표본이 목표보다 적다 | 화면이 덜 찬 채로 심사위원에게 보인다 |

개인 목록은 Spring Pageable 이라(§0-4) **끝 장까지 읽는다.** 첫 장만 보면 계정에 표본이 쌓였을 때 뒤로 밀린 것을 "없다" 고 말한다.

셋 중 하나라도 걸리면 `ok` 가 `false` 고 **종료 코드가 `3`** 이다. 채워 놓고 `0` 으로 끝내면 "준비됐다" 로 읽힌다.

```
0  정상          1  실패          2  설정 없음          3  채웠지만 되읽기에서 확인 안 됨
```

> **`--dry-run` 은 "아무것도 안 한다" 가 아니다.** 표본을 **저장하지 않을** 뿐, 로그인과 조회
> 요청은 실제로 나간다. 코스 조회는 서버에서 OSM 경로 생성을 유발할 수 있으므로, 부하
> 시험 중에는 이것도 돌리지 않는다.

## 몇 번을 돌려도 같다

`scripts/` 규칙대로 2회 실행해 결과가 같아야 한다(AGENTS 3장). 세 가지가 전부 멱등이라 그렇게 된다.

```
찜        PUT /me/favorites/{id}    이미 찜한 것을 다시 눌러도 그대로
저장 코스  POST /me/courses          geometry 가 같으면 기존 id 를 돌려준다
저장 동선  POST /itineraries         같은 (대회, 시작일, 종료일) 이면 교체한다
```

동선 **내용**은 외부 POI 조회 결과라 실행마다 조금 다를 수 있다. 개수는 1건으로 고정된다.

## 고르는 규칙

임의로 정하지 않고 이유가 있다.

- **찜할 대회** — 목록 앞에서 3건. 단 **좌표가 없는 대회는 건너뛴다.** 찜은 되는데 그 대회에서 동선을 만들면 `409 CONTEST_LOCATION_UNAVAILABLE` 이라(§5-1), 심사위원이 위저드를 눌렀을 때 오류만 본다.
  **좌표는 목록에 없어서 상세를 한 번 더 부른다**(§3-1 에는 `lat`·`lng` 가 없고 §3-4 에만 있다). 한 장에서 3건을 못 채우면 커서로 이어 본다
- **저장할 코스** — `GET /courses/near` 의 `ROUTE` 중 가까운 것부터 3건. **걷기 장소(`PLACE`)는 저장 대상이 아니다** — 코스가 아니다
- **동선 기간** — 대회 전날 ~ 대회 당일(1박 2일). 대회일을 반드시 포함해야 하고(§5-1), 당일치기면 회복일 블록이 안 나와서 §5.6 의 특징이 화면에 안 드러난다
- **테마** — `TOUR` · `FOOD`. §4.8 의 "1개 이상" 을 채우는 최소 조합이다

## 출발지 — 부산 남파랑길 2코스 시작점

```
35.114545, 129.040763   targetKm=5   radiusKm=8
```

처음에는 서울시청을 썼는데 **수도권에는 두루누비 코스가 사실상 없다**(AGENTS 6장 — 반경 8km 안 0건). 저장 코스 화면이 비면 심사위원에게는 "안 만든 기능" 으로 보인다.

이 좌표는 저장소 261개 코스와 실제 경로 빌더로 두 번 확인해 **적격 큐레이션 5건**(남파랑길 2·3·4·5 · 해파랑길 1)이 나오는 자리다(#305 리뷰 · 2026-09-07). 해운대는 2건이라 뺐다.

**5건이 곧 저장 3건은 아니다.** 실제 `/courses/near` 는 걷기 장소(`PLACE`)와 합쳐 **12개로 자르므로** ROUTE 가 몇 개 올지는 응답을 봐야 안다. 모자라면 경고로 남긴다 — 조용히 넘기면 저장 코스 화면이 왜 비었는지 아무도 모른다.

```
경고: 저장할 ROUTE 가 0건뿐이다 — 출발지를 바꾸거나 코스 동기화를 확인한다
```

그때는 `COURSE_ORIGIN` 을 다른 지역으로 바꾸거나, OSM 생성 경로가 뜨는지 확인한다.

## 이 스크립트로 끝나지 않는 것

#293 의 남은 칸이다. 표본을 채우는 것은 그중 하나다.

- [ ] 공모전 요강의 **심사 계정 제출 형식** 확인
- [ ] 전용 계정 생성 (이메일 인증 필요 — 사람이 한다)
- [x] 표본 채우기 **스크립트** — 이 파일. 오프라인 단위 테스트까지 끝났다
- [ ] 실제 심사 계정에 **표본 생성** — 스테이징 개방과 계정 준비 뒤에 돌린다. 요약 JSON 을 #293 에 남긴다
- [ ] 로그인 필요한 화면 전부 접근되는지 **기기에서** 확인
- [ ] 새 기기에 설치본을 올려 처음부터 밟기
- [ ] 계정 정보를 제출 자료 형태로 정리 (**비밀번호는 저장소에 커밋하지 않는다**)
