## 0. 데이터 소스와 저장 원칙

| 데이터 | 원천 | 런타임 방식 | 영구 저장 |
|---|---|---|---|
| 대회 | 마라톤온라인·마라톤GO | 관리자/배치가 수집·병합 | `CONTEST` 153개 canonical + `CONTEST_SOURCE` 271개 원천 |
| 대회장 좌표 | 카카오 로컬 지오코딩 | 대회 배치에서 보정 | canonical 대회에 저장 |
| 홈·인근 축제 | KTO `searchFestival2` | 백엔드 실시간 프록시 | 마스터 DB 저장 없음, 홈 단기·대회별 최대 1일 캐시 |
| 숙소 | 카카오 로컬 `AD5` | 백엔드 실시간 프록시 | 마스터 DB 저장 없음, 선택 시 동선 스냅샷 |
| 관광지·맛집·카페·웰니스 | KTO+카카오 하이브리드 | 백엔드 실시간 프록시 | 마스터 DB 저장 없음, 선택 시 동선 스냅샷 |
| 러닝코스 메타 | 두루누비 API `courseList` | 서버 시작 시+하루 1회 동기화, TTL 24시간 | 영구 마스터 DB가 아닌 캐시 |
| 러닝코스 경로 | 두루누비 GPX 파싱본 261코스 | 서버 정적 리소스, `courseId`로 메타와 결합 | 버전 관리 리소스 + 앱 축약 번들 |
| 계정·찜·동선·코스·기록 | 사용자 생성 데이터 | 자체 API | PostgreSQL |

### 저장 원칙

1. 숙소·축제·POI 외부 응답은 영구 마스터 테이블로 적재하지 않는다.
2. 사용자가 저장한 동선·코스는 선택 시점의 이름·주소·좌표·경로를 스냅샷으로 저장한다.
3. 대회는 공식 API가 없어 허가 확인을 전제로 크롤링 원천과 canonical 결과를 분리 저장한다.
4. 두루누비 GPX는 경로 좌표의 기준이며, API 메타데이터가 실패해도 코스 기능은 GPX로 계속 동작한다.
5. 캐시는 성능·쿼터·장애 격리 용도이며 데이터베이스의 영구 외부 마스터가 아니다.

## 1. 인증

### 1-1. 로그인

- **이메일**: `email`, `password` → access/refresh 토큰 + 사용자
- **카카오**: Android SDK 토큰 → 서버 검증 → 기존 `LOGIN_IDENTITY(KAKAO)` 조회
- **게스트**: 토큰 없이 홈 진입
- **상태**: 기본 / 요청 중 / 자격증명 오류 / 네트워크 오류
- 실패 메시지는 이메일 존재 여부를 노출하지 않는다.

### 1-2. 이메일 회원가입

| 단계 | 데이터 |
|---|---|
| 동의 | 이용약관·개인정보 필수, 마케팅 선택, 각 버전과 동의 시각 |
| 정보 | 이메일, 비밀번호/확인, 닉네임 |
| 인증 | 6자리 코드, 10분 만료, 5회 제한, 재발송 60초 |
| 완료 | EMAIL 로그인 수단 생성 + 자동 로그인 |

### 1-3. 카카오 회원가입

- 카카오 SDK 토큰을 서버가 회원번호로 검증한다.
- 신규 사용자는 약관·닉네임 입력 후 `LOGIN_IDENTITY(provider=KAKAO)`를 만든다.
- 카카오 이메일은 제공 동의가 있을 때만 nullable 스냅샷으로 저장하며 자체 이메일 인증을 요구하지 않는다.

### 1-4. 로그인 수단 연결

- 이메일과 카카오 이메일이 같아도 **자동 병합하지 않는다**.
- 로그인된 사용자가 마이에서 카카오 연결을 명시적으로 시작한다.
- `(provider, subject)`는 전역 유니크이며 사용자에게 로그인 수단이 최소 1개 남아야 한다.
- 충돌 시 `409 IDENTITY_ALREADY_LINKED`.

### 1-5. 비밀번호 찾기

- 가입 여부와 무관하게 재설정 메일 요청은 동일한 `202` 응답.
- 1회용 링크 토큰은 30분, 해시 저장, 사용 후 `consumedAt`.
- 비밀번호 변경 후 해당 사용자의 refresh token을 전부 revoke.

## 2. 홈

- **검색**: 대회명·장소·지역 → 캘린더로 `q` 전달
- **퀵메뉴**: 달력 / 지도 / 코스 / 관광
- **마감 임박**: 파생 접수상태 `OPEN`, `applyEnd ASC`, 최대 4건
- **축제**: KTO `searchFestival2`, 축제명·기간·지역·이미지·진행중·출처
- **숨은 값**: contest id, contentId, 캐시 시각

🆕 **구현 추가 요구사항**

- `축제를 불러오는 중…`
- 빈 상태 `이번 달에 표시할 축제가 없어요.`
- 오류 `축제를 불러오지 못했어요.` + `다시 시도`

## 3. 캘린더

### 리스트

| 표시 | 서버 필드 |
|---|---|
| 월·일·요일 | `contestDate` 파생 |
| 대회명·지역·장소 | canonical `CONTEST` |
| 종목 | `events[]` |
| 접수상태 | 공통 `regStatus` 계산식 |
| 출처 | `sources[]` + 최신 `checkedAt` |
| 찜 | 로그인 사용자 `favorite` |

- 검색·종목 OR·접수 가능·17개 지역 필터는 공통 Predicate를 사용한다.
- 대회 목록은 불투명 커서 `nextCursor`, 기본 20·최대 50.
- `date`가 있으면 `contestDate = date`.

### 월간

- 날짜별 건수는 목록과 동일한 Predicate를 공유한다.
- 선택일 재탭 시 선택 해제.
- 목록/날짜/월 0건 상태를 구분한다.

## 4. 대회 상세

- canonical 대회 정보와 `sources[]`를 표시한다.
- 공식 페이지, 찜, 동선 만들기.
- 인근 축제는 `searchFestival2(대회일±14일)` → 기간 교집합 → Haversine 40km → 거리순 6건.
- 사용자는 대회 생성·수정·삭제 API에 접근할 수 없다.
- 대회 갱신은 관리자·배치만 수행한다.
- Loading/Empty/Error/Retry 상태를 모두 제공한다.

## 5. 동선 위저드

### W1 기간

- `pattern`, `startDate`, `endDate`
- 패턴 5종과 직접 선택.

### W2 종목·취향

- `event`: `K5/K10/HALF/FULL`
- `themes[]`: `TOUR/FOOD/CAFE/WELLNESS/NATURE/HISTORY`
- 화면 상태·도메인·API 모두 `themes` 명칭으로 통일한다.

### W3 숙소

- 카카오 로컬 `AD5`, 대회장 중심 거리순 최대 8건.
- `hotel`은 선택이며 `null`이면 대회장 중심으로 생성한다.
- 선택 시 `name/address/lat/lng` 스냅샷을 전달한다.

🆕 **구현 추가 요구사항**

- Loading `숙소를 찾는 중…`
- Empty `조건에 맞는 숙소가 없어요.` + 숙소 없이 진행
- Error `숙소를 불러오지 못했어요.` + 다시 시도/숙소 없이 진행

## 6. 동선 결과·편집

- 지도·일자 탭·타임라인·회복 상태·연계 카드.
- 생성 API는 DB에 저장하지 않고 DTO만 반환한다.
- 저장 CTA가 트리 전체를 한 번 저장한다.
- 같은 `(user, contest, startDate, endDate)`는 유니크이며 기존 동선을 교체한다.

### RACE 블록 정책

- `blockType=RACE`, `systemManaged=true`, `contestId` 필수.
- 사용자는 교체·삭제·드래그 순서 변경을 할 수 없다.
- 편집 UI에서 드래그 그립·교체·삭제 버튼을 전부 숨긴다.
- 서버는 PATCH/DELETE/순서 이동 시 `409 SYSTEM_BLOCK_IMMUTABLE`.
- 제목·대회장·출발시간은 저장 스냅샷을 신뢰하지 않고 최신 `CONTEST`에서 조합한다.

### USER 블록 정책

- 교체·추가·삭제·순서 변경 가능.
- 후보 시트는 카테고리 7종과 실시간 POI 최대 8건.
- 순서 PUT은 해당 일자의 USER 블록 집합과 일치해야 하며 RACE 위치는 유지한다.

🆕 **구현 추가 요구사항**: 후보 시트 Loading/Empty/Error/Retry.

## 7. 러닝코스

### 데이터 결합

```text
두루누비 API courseList 메타데이터
             + courseId
GPX 파싱본 경로 좌표·진입점
             ↓
런닝구 백엔드 단일 Course DTO
```

- 서버 시작 시와 하루 1회 동기화.
- API 메타데이터는 TTL 24시간 캐시.
- API 장애·미매칭이면 GPX fallback 메타데이터를 사용한다.
- `API_GPX`, `GPX_ONLY`, `API_ONLY` 매칭 통계를 로그로 남긴다.
- `API_ONLY`는 경로가 없으므로 지도·추천·뛰기에서 제외한다.

### 내 주변

- GPS/검색/프리셋 출발지 + 1~21km 목표.
- GPX 경로에서 최근접 진입점과 왕복 경로를 생성.
- 추천 코스, 짧은 코스 경고, 대체 코스, 걷기 스팟.

### 지역별

- 지역 칩·개수, 거리순 목록, 빈 상태.

### 오프라인

- 앱은 GPX 파싱본 축약 JSON/polyline을 번들한다.
- 네트워크 불가 시 API 최신 메타 대신 번들 값을 사용한다.

## 8. GPS 기록

- 기록 중: 경과 시간·거리·평균 페이스·종료.
- 앱은 5m 이동 필터와 포그라운드 서비스를 사용한다.
- 서버는 좌표 2개 이상·한국 영역을 검증하고 방어적 재필터 후 polyline 저장.
- 네트워크 불가 시 로컬에 `pendingUpload`로 저장하고 로그인·네트워크 복구 후 업로드한다.

## 9. 마이 (S10)

마이 진입은 인증이 필요하다.

### 프로필

- 닉네임, 가입/연결 로그인 수단, 정보 수정 버튼.
- 정보 수정:
  - 닉네임
  - 마케팅 동의
  - EMAIL 사용자의 비밀번호
  - 카카오 연결·해제
  - 로그아웃
  - 탈퇴
- 이메일 주소 변경은 MVP 범위 밖.

### 세그먼트

| 탭 | 데이터 |
|---|---|
| 동선 | ITINERARY 목록·열기·삭제 |
| 러닝코스 | SAVED_COURSE + RUN_RECORD |
| 찜한 대회 | FAVORITE ⋈ canonical CONTEST |

- 개인 목록은 `createdAt DESC, id DESC` 페이지 방식.
- 마이 읽기는 마지막 성공 Room 캐시를 오프라인 표시할 수 있다.
- 오프라인 쓰기는 GPS pending upload 외에는 MVP에서 제공하지 않는다.
