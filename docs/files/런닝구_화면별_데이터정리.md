## 0. 데이터 소스와 저장 원칙

| 데이터 | 원천 | 런타임 방식 | 영구 저장 |
|---|---|---|---|
| 대회 | 마라톤온라인·마라톤GO | 관리자/배치가 수집·병합 | `CONTEST` 153개 canonical + `CONTEST_SOURCE` 271개 원천 |
| 대회장 좌표 | 카카오 로컬 지오코딩 | 대회 배치에서 보정 | canonical 대회에 저장 |
| 홈·인근 축제 | KTO `searchFestival2` | 백엔드 실시간 프록시 | 마스터 DB 저장 없음, 홈 단기·대회별 최대 1일 캐시 |
| 숙소 | 카카오 로컬 `AD5` | 백엔드 실시간 프록시 | 마스터 DB 저장 없음, 선택 시 동선 스냅샷 |
| 관광지·맛집·카페·웰니스 | KTO+카카오 하이브리드 | 백엔드 실시간 프록시 | 마스터 DB 저장 없음, 선택 시 동선 스냅샷 |
| 큐레이션 코스 메타 | 두루누비 API `courseList` | 서버 시작 시+하루 1회 동기화, TTL 24시간 | 영구 마스터 DB가 아닌 캐시 |
| 큐레이션 코스 경로 | 두루누비 GPX 261코스 + 라이선스 검증 GPX | 원천 메타와 결합해 지역 목록·출발지 주변 우선 후보 제공 | 버전 관리 리소스 + 앱 축약 번들 |
| OSM 도시 경로 | 대한민국 OSM PBF + SRTM | 외부 builder가 만든 버전별 graph artifact로 적격 큐레이션 0건일 때 내부 GraphHopper가 요청 시점에 최대 1건 생성 | EC2에는 검증된 graph artifact만 보관, 생성 응답은 임시 |
| 계정·찜·동선·저장 코스 | 사용자 생성 P0 데이터 | 자체 API | PostgreSQL |

### 저장 원칙

1. 숙소·축제·POI 외부 응답은 영구 마스터 테이블로 적재하지 않는다.
2. 사용자가 저장한 동선·코스는 선택 시점의 이름·주소·좌표·경로를 스냅샷으로 저장한다.
3. 대회는 공식 API가 없어 허가 확인을 전제로 크롤링 원천과 canonical 결과를 분리 저장한다.
4. 큐레이션 GPX는 경로 좌표의 기준이며, 두루누비 API 메타데이터가 실패해도 GPX fallback으로 계속 동작한다.
5. OSM 생성 경로는 코스 마스터에 적재하지 않고, 사용자가 저장한 경우에만 `SAVED_COURSE` snapshot으로 보존한다.
6. 저장 코스 attribution은 서버가 검증된 원천에서 완성 문구 배열로 생성해 `JSONB NOT NULL DEFAULT '[]'` snapshot으로 함께 보존한다.
7. 대회 source는 승인된 완전 snapshot에서 2회 연속 누락될 때만 비활성화한다. 실패·부분 snapshot은 횟수에 포함하지 않고 재등장 시 즉시 복구하며, canonical·찜·동선은 물리 삭제하지 않는다.
8. 캐시는 성능·쿼터·장애 격리 용도이며 데이터베이스의 영구 외부 마스터가 아니다.

## 1. 인증

### 1-1. 로그인

- **이메일**: `email`, `password` → access/refresh 토큰 + 사용자
- **카카오**: Android SDK 토큰 → 서버 검증 → 기존 `LOGIN_IDENTITY(KAKAO)` 조회
- **게스트**: 토큰 없이 홈 진입
- **상태**: 기본 / 요청 중 / 자격증명 오류 / 네트워크 오류
- 실패 메시지는 이메일 존재 여부를 노출하지 않는다.

### 1-2. 이메일 회원가입

| 단계 | 데이터 |
|---|---|
| 동의 | 이용약관·개인정보 필수, 마케팅 선택, 각 버전과 동의 시각 |
| 정보 | 이메일, 비밀번호/확인, 닉네임 |
| 인증 | 6자리 코드, 10분 만료, 5회 제한, 재발송 60초 |
| 완료 | EMAIL 로그인 수단 생성 + 자동 로그인 |

### 1-3. 카카오 회원가입

- 카카오 SDK 토큰을 서버가 회원번호로 검증한다.
- 신규 사용자는 약관·닉네임 입력 후 `LOGIN_IDENTITY(provider=KAKAO)`를 만든다.
- 카카오 이메일은 제공 동의가 있을 때만 nullable 스냅샷으로 저장하며 자체 이메일 인증을 요구하지 않는다.

### 1-4. 가입 로그인 방식

- 사용자는 가입 시 EMAIL 또는 KAKAO 중 하나만 선택한다.
- `USER:LOGIN_IDENTITY`는 1:1이며 `user_id`와 `(provider, provider_subject)`는 각각 UNIQUE다.
- P0에서는 로그인 수단 연결·추가·해제·전환을 지원하지 않는다.
- 이메일과 카카오 이메일이 같아도 서로 다른 provider 계정을 자동 병합하지 않는다.
- 대표 이메일은 EMAIL의 정규화 이메일 또는 KAKAO의 nullable 이메일 스냅샷에서 파생한다. KAKAO 가입자에게 별도 이메일 입력·인증을 요구하지 않는다.

### 1-5. 비밀번호 찾기

- 가입 여부와 무관하게 재설정 메일 요청은 동일한 `202` 응답.
- 1회용 링크 토큰은 30분, 해시 저장, 사용 후 `consumedAt`.
- 비밀번호 변경 후 해당 사용자의 refresh token을 전부 revoke.

## 4. 대회 상세

- canonical 대회 정보와 `sources[]`를 표시한다.
- 공식 페이지, 찜, 동선 만들기.
- 인근 축제는 `searchFestival2(대회일±14일)` → 기간 교집합 → Haversine 40km → 거리순 6건.
- 사용자는 대회 생성·수정·삭제 API에 접근할 수 없다.
- 대회 갱신은 관리자·배치만 수행한다.
- 찜·저장 동선에서 비활성 상세 조회는 유지한다. `active=false`면 흐림과 "정보 제공 종료"를 표시하고 동선 CTA를 비활성화하며 인근 축제를 호출하지 않는다.
- Loading/Empty/Error/Retry 상태를 모두 제공한다.

## 6. 동선 결과·편집

- 지도·일자 탭·타임라인·회복 상태·연계 카드.
- 생성 API는 DB에 저장하지 않고 DTO만 반환한다.
- 저장 CTA가 트리 전체를 한 번 저장한다.
- 같은 `(user, contest, startDate, endDate)`는 유니크이며 기존 동선을 교체한다.
- 저장 시 region·recovery·호텔·일자·USER/RACE 블록 전체를 snapshot으로 보존한다. 목록의 대회명과 상세의 현재 대회 메타·active는 canonical에서 파생한다.

### RACE 블록 정책

- `blockType=RACE`, `systemManaged=true`, `contestId` 필수.
- 사용자는 교체·삭제·드래그 순서 변경을 할 수 없다.
- 편집 UI에서 드래그 그립·교체·삭제 버튼을 전부 숨긴다.
- 서버는 PATCH/DELETE/순서 이동 시 `409 SYSTEM_BLOCK_IMMUTABLE`.
- 최초 저장·재생성 교체 때 서버가 canonical로 RACE를 구성하고 저장 이후에는 날짜·시간·장소·주소·좌표 snapshot을 유지한다. canonical 변경을 기존 타임라인에 자동 반영하지 않는다.

### USER 블록 정책

- 교체·추가·삭제·순서 변경 가능.
- 후보 시트는 카테고리 7종과 실시간 POI 최대 8건.
- 순서 PUT은 해당 일자의 USER 블록 집합과 일치해야 하며 RACE 위치는 유지한다.

🆕 **구현 추가 요구사항**: 후보 시트 Loading/Empty/Error/Retry.

### 대회 변경·재생성

- 서버는 저장된 RACE/region snapshot과 최신 canonical의 날짜·시간·장소·지역·좌표가 다르면 `needsRegeneration=true`를 파생한다. 이름만 변경되거나 active만 달라진 경우는 제외한다.
- 마이 동선 카드에는 "대회 변경" 배지를, 상세에는 최신 대회 정보와 저장 당시 동선을 함께 표시한다.
- [다시 만들기] 전에 "직접 고친 장소는 사라져요. 다시 만들까요?"를 확인한다. 생성 미리보기 동안 기존 동선은 유지하고, 최종 저장 때 `PUT /api/itineraries/{id}`로 같은 id의 트리를 교체한다. USER 편집은 자동 병합하지 않는다.

## 7. 러닝코스

### 데이터 결합

```text
두루누비 API courseList 메타데이터 + 라이선스 검증 큐레이션 GPX
             ↓ 적격 큐레이션 왕복 경로
       적격 경로 0건이면
대한민국 OSM+SRTM GraphHopper 순환 경로 최대 1건
             +
카카오 걷기 스팟
             ↓
런닝구 백엔드 /courses/near 단일 응답
```

- 큐레이션 메타는 서버 시작 시와 하루 1회 동기화하고 TTL 24시간 캐시를 사용한다.
- API 장애·미매칭이면 GPX fallback 메타데이터를 사용한다.
- `API_GPX`, `GPX_ONLY`, `API_ONLY` 매칭 통계를 로그로 남기며 경로가 없는 `API_ONLY`는 서비스에서 제외한다.
- OSM 생성은 적격 큐레이션 0건일 때만 실행하며 결과를 지역 목록·코스 마스터에 적재하지 않는다.
- GraphHopper 장애는 큐레이션·카카오 장소와 격리하고 `degradedSources`로 전달한다.

### 출발지 주변

- 검색/프리셋/S7 숙소 출발지 + 1~21km 목표거리만 입력한다. **기기 위치는 쓰지 않는다**(결정-56). P0 난이도 입력은 없다.
- 큐레이션은 GPX에서 최근접 진입점과 왕복 경로를 만들고 상승 `<50m/km`인 경로만 자동 추천한다.
- 적격 큐레이션이 없으면 GraphHopper 후보 중 거리 75~125%·상승 `<50m/km`·차도 `≤10%`·실제 회전 `≤6회/km`를 모두 통과한 경로만 최대 1건 반환한다.
- 큐레이션·OSM 경로와 걷기 스팟을 거리순으로 합쳐 최대 12건을 반환한다.

### 지역별

- 지역 칩·개수, 거리순 목록, 빈 상태.
- `GET /api/courses`의 `attributions[]` 완성 문구를 배열 순서대로 `" · "`로 연결해 목록 하단에 표시한다.

### 저장 코스 중복 판정

- 백엔드가 경로 geometry만으로 `routeFingerprint`를 생성한다.
- 좌표를 확정 정밀도로 정규화하고 연속 중복 좌표만 제거하며 진행 순서를 유지한다.
- 반대 방향 경로는 다른 경로다.
- 코스명·지역·난이도·시간·상승고도·거리·`dataSource`는 fingerprint 입력에서 제외한다.
- 저장 형식은 `v1:<SHA-256 lowercase hex 64자>`, DB 타입은 `VARCHAR(67)`이다.
- attribution은 서버가 저장 시점 원천에서 확정하고 클라이언트 입력은 신뢰하지 않는다. 상세에만 `List<String>`으로 반환하고 목록·fingerprint에서는 제외하며, 이후 문구 변경을 기존 snapshot에 소급하지 않는다.
- `pathPolyline`은 고도 없는 2D Google Encoded Polyline precision 5(E5)다. fingerprint canonical geometry는 연속 중복점을 제거한 뒤 각 좌표를 소수점 5자리 `lat,lng`로 쓰고 `;`로 연결한 UTF-8 문자열이다.
- `elevationProfileM`은 최대 100개 정수 미터 배열·미보유 시 `[]`이며 PostgreSQL `JSONB NOT NULL DEFAULT '[]'`로 저장한다(확정-DB-01, SPEC 결정-33 08-23 재개정, 이슈 #62).

### 오프라인

- 앱은 GPX 파싱본 축약 JSON/polyline을 번들한다.
- 네트워크 불가 시 API 최신 메타 대신 번들 값을 사용한다.

  - 닉네임
  - 마케팅 동의
  - EMAIL 사용자의 비밀번호
  - 로그아웃
  - 탈퇴
- 로그인 방식 변경과 이메일 주소 변경은 MVP 범위 밖.
