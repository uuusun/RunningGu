Android 코드는 EC2에 올리는 대상이 아니다. EC2에는 백엔드·DB·GraphHopper 등이 있고, Android APK는 휴대전화에서 실행되며 HTTPS로 서버를 호출한다. 앱만을 위한 별도 EC2·웹 프런트 서버를 추가할 필요는 없다.

백업 확인 근거: [Android Auto Backup](https://developer.android.com/identity/data/autobackup)은 기본적으로 앱 내부 파일·DB 등을 백업 대상으로 설명하며 Android 12 이상은 클라우드 백업과 기기 이전을 나누어 제어한다. 위 설정은 데이터가 실제 업로드됐다는 증거가 아니라 백업에서 제외되지 않은 코드 상태의 발견이다. P0 세션 저장 방식 자체는 #77의 기존 결정이므로 이번 확인에서 암호화 라이브러리 추가나 저장 방식 변경을 하지 않았다.

지금 준비할 순서는 **앱 백업 정책·릴리스 검사 수정안 → 카카오 새 키 대조**다. SES 신청은 22:33 KST에 제출해 심사 중이며 결과·추가 정보 요청을 확인해야 한다. 4GiB 시험과 무관한 코드 검토·로컬 빌드 준비는 진행할 수 있고, 측정 EC2의 변경·추가 트래픽은 시험 종료까지 대기한다. 앱 코어/CI 변경은 민지 담당이므로 실제 수정 착수 시 기존 역할 경계와 사용자 승인 범위를 따른다.

## 4GiB 검증 중 진행 순서

아래는 2026-09-05 당시의 진행 기록이다. 4GiB 채택과 별도 운영 EC2 생성 결과는 문서 첫 절의 2026-09-10 결정을 따른다.

2026-09-05 선경 확인: 4GiB 검증은 진행 중이며 운영 사양은 아직 정할 수 없다. 사양 결정에 의존하는 운영 자원 생성은 대기하고, 아래 준비를 먼저 진행할 수 있다.

- 측정 중인 EC2의 배포 버전·메모리 설정·기동 상태를 유지한다. #297 artifact는 준비됐지만, 해당 EC2를 대상으로 하는 재배포·재시작은 검증 종료 후 진행한다. 같은 서버를 사용하는 APK 수동 검증도 부하 측정 구간 밖에서 진행해 측정 조건을 유지한다.
- 공개 서비스 소개·개인정보처리방침 URL 준비, SES 신청 내용과 반송·신고 처리 경로 확인은 EC2 메모리 사양 확정에 의존하지 않는다.
- 원스토어 상품 입력은 후속 사용자 결정에 따라 앱 구현 완료 후 재개한다. 준비한 자료·상품은 보존한다. 약관의 앱·서버 버전 정합성 확인은 코드 배포 준비로 계속 다룬다.
- 서명 키의 외부 백업과 비밀번호 별도 보관은 서버 검증과 독립적으로 완료할 수 있다.
- 검증 종료 후 결과를 먼저 보존한다. 4GiB 채택은 실행서의 동일 계약 시나리오 3회 연속 통과가 전제이며, 운영 사양과 상시 운영 월 예상비용을 함께 확정한다. 4GiB가 통과하지 못하면 기존 8GiB 검증 결과와 실패 원인을 기준으로 판단하며 운영 사양을 자동 확정하지 않는다.
- 이후 #297 스테이징 배포·API 스모크 확인과 운영 환경 구성을 진행한다. 운영 주소로 같은 출시 키를 사용해 APK를 다시 만들고 로그인·지도·전체 화면을 검증한 뒤 원스토어 제출을 진행한다.

## 서명 키와 앱팀 검증

- #295는 `77da13d`의 **unsigned APK** 기록이다. 해당 PC에 릴리스 keystore와 카카오 네이티브 키가 없어 건모에게 전달 가능한 APK가 아니다.

- 기존 키 원본은 민지의 회사 PC에 있으며 현재 접근할 수 없다. 이후 선경의 명시적인 생성 요청으로 아래 신규 출시용 keystore를 생성했다. 키 파일·비밀번호는 이 기록과 Git에 넣지 않는다.
- 기존 #108 분담은 APK 빌드 민지, 키 보관 책임 선경, 카카오 콘솔 등록·기기 검증 건모다. 이번에는 민지가 현재 작업할 수 없다는 선경의 설명에 따라 선경 PC에서 서명 APK를 제작했다. 카카오 콘솔 등록·기기 검증은 건모가 이어간다.
- 아래 콘솔 확인 결과, 확인한 원스토어·Google Play 계정에는 기존 등록 앱이 없다. 다른 계정에 등록한 앱까지 조사한 것은 아니다. 이번 원스토어 최초 출시를 위해 새 키를 생성했고, 해당 키와 staging 주소를 적용한 서명 APK 제작까지 완료했다.

- 구 키 서명 APK가 설치된 검증 기기는 새 서명의 APK로 일반 업데이트되지 않을 수 있다. 기존 앱·표본 데이터를 임의로 삭제하지 않고 별도 검증 기기/AVD를 사용한다.

- 키 외부 백업: 저장소 밖 `C:\Users\SSAFY\RunningGu-signing\external-backup`에 기존 암호화 PKCS12 키·공개 인증서·복구 안내 3개만 준비했다. 비밀번호와 DPAPI 암호문은 포함하지 않았다. 복사본의 개인키 서명·변조 거부·잘못된 비밀번호 거부를 확인했고, 권한 재설정의 재실행 오류를 수정한 뒤 두 차례 같은 키 해시와 성공 결과를 확인했다.
- 개인 Drive: 선경 개인 계정의 전용 폴더에 `external-backup`의 3개 파일을 업로드했고, 상위·하위 폴더 모두 소유자 1명·일반 액세스 제한됨을 확인했다. 이후 Drive의 키를 다운로드해 원본 파일 해시·인증서 일치, 실제 개인키 서명·검증 성공, 변조 메시지·잘못된 비밀번호 거부를 두 차례 확인했다. 다운로드 검증본은 저장소 밖의 제한된 키 폴더에 보관했다. 비밀번호 별도 보관은 사용자 완료 응답 기준이다. 비공개 Drive 주소·비밀번호는 Git 문서에 적지 않는다.

### 스토어 업로드 이력 확인 현황

- 최초 접근 시에는 두 콘솔 모두 로그인이 필요했으나, 선경의 가입·로그인 완료 후 2026-09-05 아래 내용을 직접 확인했다.
- 원스토어: 로그인된 `Apps > 상품현황`에 **등록된 상품이 없습니다**와 첫 상품 등록 안내가 표시된다. 이 계정에는 서명 설정·바이너리를 확인할 기존 상품이 없다.
- Google Play: 유선경 개인 개발자 계정의 홈에 **첫 번째 앱 만들기**와 등록 앱이 없다는 안내가 표시된다. 활동 로그 조회 기간은 2026-08-07~2026-09-05이며, 2026-08-29 계정 생성 1건과 권한 변경 2건, 총 3건만 있다. 계정 생성일부터 확인일까지 앱 생성·APK/AAB 업로드 기록은 없다.
- Google Play 계정 설정은 아직 미완료다. 본인 확인(공문서 제출), 실제 Android 휴대기기 접근 확인, 연락처 전화번호 인증이 남아 있다. 전화번호 인증은 다른 인증 작업이 완료된 뒤 진행하도록 안내된다. 첫 앱 만들기 버튼은 비활성화돼 있다.
- 기존 Play 본인 인증 입력 화면은 보존하고 별도 탭에서 앱 목록·활동 로그만 읽었다. 인증 동의·문서 제출은 실행하지 않았다.
- 원스토어 공식 공지에서 개발자센터가 2024-09-24 `dev.onestore.co.kr`에서 `dev.onestore.net`으로 이전했음을 확인했다.
- #253의 2026-09-05 민지 댓글은 기존 키 원본이 회사 Windows PC에 있고 주말에는 접근할 수 없다고 설명한다. 서명 키·APK 제작 기록은 있지만, 이 댓글만으로 스토어 업로드 여부를 판단할 수 없다.
- 확인 범위는 로그인한 위 두 계정이다. 다른 개발자 계정의 업로드 이력이나 패키지 이름의 전역 사용 가능 여부까지 확인한 것은 아니다.
- 콘솔 확인 과정에서는 앱 등록·업로드·서명 키 생성 또는 교체를 실행하지 않았다. 이후 별도 사용자 요청으로 신규 keystore를 생성한 결과는 위에 기록했다.
