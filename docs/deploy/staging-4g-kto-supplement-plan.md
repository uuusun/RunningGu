# 4GiB 공공데이터·동선 생성 245건 보완 검증

**실행 완료:** 245건 모두 성공, KTO 실제 호출 38회 정상, 백업/WAL·가드 OFF·복귀 완료.
측정 범위에서는 현재 4GiB 유지 가능으로 판단했다.
[최종 결과와 범위의 한계](evidence/api-load-ec2-4g-20260907-kto-supplement.md)를 따른다.

2026-09-07 사용자는 앞선 부분 부하에서 제외한 245건의 재검증을 요청했다.
별도 run의 `app-capacity-v5-kto-only`로 실행하며 이전 1,855건 증거를 변경하지 않는다.

- 승인 fixture/hash와 원래 2,100건 시간표/hash는 그대로 유지한다.
- 원래 슬롯에서 festival 70, poi 70, itinerary_generate 105건만 선택한다.
- 준비 5분 35건 + 본 시험 30분 210건, 분당 7건, 최대 동시 진행 4개다.
- 기존 입력·캐시 정책·서버 SHA·graph·JVM·cgroup·swap을 바꾸지 않는다.
- 세 API는 미인증 조회/동선 생성 계약이다. 계정 로그인·갱신·즐겨찾기 변경은 실행하지 않는다.
- 연결 확인 뒤 기존 v3 서버 가드의 KTO/카카오 한도·실제 송신 계측·만료 복구를 사용한다.
  서버 가드의 acceptancePolicy는 app-capacity-v3, PC 실행 profile은 v5로 구분한다.
- 정상 코스 자동 동기화를 유지한다. 가드 활성화 시 동기화·축제 preflight까지 성공해야 시작한다.
- EC2 40분/5초 계측, 부하 중 full backup 1회·WAL 3회를 유지한다.
- 지연·내용 검증 실패·GC·일시적 메모리 감소는 기록한다. 실패 요청을 재시도하지 않는다.
  기존 가드 예외가 공통 HTTP 500이므로 500은 보호 확인을 위해 신규 송신을 중단하고
  가드 원본과 대조한다. 실제 가드 차단을 우회하거나 counter를 초기화하지 않는다.
- OOM으로 서비스 종료·미복구·비정상 재시작은 보호 중단한다. 중단/예외도 전체 시간표와
  요청별 송신·완료·성공·실패·미실행·부분 통계를 보존한다.
- 종료 후 즉시 가드 OFF·backend 재기동·readiness·HTTPS와 임시 작업 종료를 확인한다.
- 공공데이터 운영자에게 문의·메일·댓글을 보내지 않는다.

이 시험은 빠졌던 기능을 보완한다. 서로 다른 시각의 1,855건과 245건을 합쳐
원래 60요청/분의 2,100건 혼합 부하를 완료했다고 표시하지 않는다.
245건의 API 성능·GC/메모리·실제 외부 송신·오류를 이전 결과와 함께 평가하되,
전체 혼합 부하와의 차이를 최종 RAM 판단에 남긴다.
