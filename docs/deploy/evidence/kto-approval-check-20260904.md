# KTO 개인 계정 승인 확인 — 2026-09-04

> 승인 목록·표시 한도와 **재발급 키의 소량 API 호출 4건 성공**을 확인했다.
> 이후 승인된 **EC2 키 교체·백엔드 재시작·HTTPS API 5항목 확인까지 완료**했다.

## 확인 방법과 결과

운영책임자가 로그인한 공공데이터포털의 `마이페이지 → 활용신청 현황 → 승인된 서비스 상세`를
읽기 전용으로 확인했다. 공개 데이터 소개의 기본 한도가 아니라 해당 계정의 신청 상세 값이다.
계정의 전체 승인 API는 10개이며 아래 세 서비스를 확인했다.

| 서비스 | 상태·유형 | 필요한 상세 기능의 표시 한도 |
|---|---|---|
| 한국관광공사_국문 관광정보 서비스_GW (`KorService2`) | 승인·개발계정 | `locationBasedList2`, `searchFestival2`: 각각 일일 트래픽 1,000 |

## 인증키 취급 사고와 중단 지점

마이페이지 브라우저 연결을 재설정하면서 자동 출력된 접근성 상태에 개인 일반 인증키 원문이
포함됐다. 별도 조회에서는 값을 가렸지만 자동 초기 상태 출력에는 적용되지 않았다.
에이전트가 운영책임자에게 즉시 알렸으며, 해당 키를 호출·배포에 사용하지 않았다.
키 원문·부분값·스크린샷은 이 문서나 저장소에 남기지 않는다.

`AGENTS.md` §8에 따라 해당 키는 폐기·재발급이 필요하다. 인증정보 변경은 사용자가 직접 수행하도록
`인증키 발급현황`의 `일반 인증키 재발급하기` 화면까지 준비했으며, 재발급 버튼은 누르지 않았다.
이후 운영책임자가 대화에서 **재발급 완료**를 알렸다. 새 인증키 화면을 다시 조회하거나 원문을
수집하지 않았으며, 기존 키 무효화를 실제 API 호출로 독립 확인한 것은 아니다. 기존 키를 쓰는
다른 프로젝트가 있다면 함께 교체해야 한다. 팀 공유 시에도 키 원문 없이 사고·조치 상태만 전달한다.

재개 순서는 사용자 재발급·기존 키 무효화 확인 → 비공개 전달/설정 경로 준비 → 소량 인증 시험 →
승인된 EC2 환경변수 교체와 백엔드 재시작 → 외부 할당량·고정 요청 세트 확정이다.
키를 채팅·Git·SSM Run Command 명령문에 넣지 않는다. 재발급 후에도 전체 마이페이지나
인증키 표를 출력하지 않고 승인·한도 등 필요한 영역만 읽는다.

## 재발급 후 비공개 입력 준비

- 운영책임자의 재발급 완료 응답 뒤 새 키 화면은 조회하지 않았다.

  `GetPassWarning`을 오류로 처리해 입력을 중단한다. 사용자가 키를 직접 입력·제출한다.
- 제출되면 `/run` 아래 임시 디렉터리(0700)에 후보 키 파일(0600)을 배타적으로 생성한다.
  새 키는 명령 인자·shell history·도구 출력에 넣지 않는다. 기존 파일은 덮어쓰지 않는다.
- 최초 준비 시 `New KTO key (Decoding; input hidden):`에서 사용자 입력을 대기했다.
  이후 사용자가 직접 실행할 입력 코드를 요청해 제공했고, 사용자 입력 완료 응답 뒤

  키 원문은 읽어 출력하지 않았다. 이 입력 단계에서는 환경변수 교체·백엔드 재시작을 하지 않았다.
- 입력 완료 후 소량 호출 검증과 환경변수 반영을 마치면 후보 파일을 정리한다.

### 사용자 요청에 따른 입력란 재준비

기존 터미널 입력이 응답하지 않아 해당 Session Manager 접속 세션만 종료하고 같은 EC2에 새 세션을
열었다. EC2·백엔드·GraphHopper 중지나 재시작은 하지 않았다. 새 세션에서 비밀값 없는 `printf`
시험 명령을 `Ctrl+V`와 Enter로 실행해 출력까지 확인한 뒤 숨김 입력 프롬프트를 다시 준비했다.
클립보드에는 준비용 시험/도우미 명령이 사용됐으므로 사용자에게 새 Decoding 키를 다시 복사하도록
안내한다. 이전 입력의 후보 저장 성공은 확인하지 않았고 기존 후보 파일을 삭제하거나 덮어쓰지 않았다.

### 실행 과정의 실패와 경계

처음 브라우저 터미널에 전달한 긴 단일 줄 검사 명령은 결과를 내지 못하고 `>` 이어 입력 상태에

최종적으로 **비밀값이 아닌 검사 코드만** Base64로 전달하고, CLI 미리보기에서 명령 1개·원문

SSM 명령·출력에 포함하지 않았다. Base64는 키를 숨기는 수단으로 사용하지 않았다.
