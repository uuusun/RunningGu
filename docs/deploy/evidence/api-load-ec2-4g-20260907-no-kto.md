# 4GiB 부분 부하 결과 — 공공데이터 호출 제외 (2026-09-07)

**판정: 이번에 선택한 기능·요청량에서는 현재 4GiB 설정 유지 가능.**
1,855건을 모두 정상 처리했고, 본 시험 응답시간 목표·계정 분리·백업/WAL·종료 복귀를

현재 결과만으로 설정 변경이나 RAM 증설을 요구할 근거는 없다.

공공데이터를 호출하는 앱 요청 245건을 사용자 결정으로 제외했다. **원래 2,100건 전체 부하,
동선 생성 및 KTO 기능을 포함한 전체 앱 용량 합격은 아니다.** 자동 코스 동기화도 시험 동안
꺼졌으므로 그 작업과의 동시 부하는 이번 결론에 포함하지 않는다. 4GiB의 부하가 전혀 없다는
뜻이 아니라, 측정한 부하를 여유를 남기고 처리했다는 뜻이다.

단순 합계를 호스트 전체 메모리 사용량으로 보지 않는다.

GH Full GC와 겹친 주변 OSM 요청은 **259.746ms, HTTP 200**이었다.
그 전후 5초의 9요청도 모두 성공했고 가장 긴 요청은 338.118ms였다.
backend Full GC 전후 5초의 10요청은 모두 성공했으며 가장 긴 요청은 84.570ms였다.
짧은 정지가 있었으나 요청 오류·timeout·목표 위반·서비스 회복 실패로 이어지지 않았다.

부하 중 모든 GC pause 합계는 backend **14회/237.264ms**, GH **148회/3,170.685ms**다.
Full GC만 세면 각 1회, 합계 **144.313ms**다. GH의 가장 긴 개별 pause는
Full GC가 아닌 **89.919ms**였다. backend GC 후 heap은 48–49MiB였다.
GH는 Full GC 후 다시 할당·회수를 반복했고, GC 후 heap은 한때 2,001MiB까지
올랐으나 마지막 GC 후에는 **1,227MiB**였다. 이 35분 자료에서 회복 실패는 관측되지
않았으며, 이를 장기간 누수가 없다는 증명으로 확대하지 않는다.

호스트 CPU 최고 12.392% 표본 전후 5초의 9요청도 모두 성공(최대 271.238ms)했다.
API/GC 인접 비교는 PC 시각과 서버 UTC를 사용한 ±5초 대조이며, 요청 지연의
인과관계를 개별 GC에 정확히 배분하는 추적 자료는 아니다.

### 종료 경계와 계획된 재기동을 구분한 기록

40분 전체 최저 MemAvailable은 **26.465%**다. 실제 부하 내부 최저 26.493%와 구분한다.
전체 최고 CPU **97.533%**는 **00:37:00**, 계획된 backend 재기동 중이었다.
부하가 계속되는 동안 CPU가 97%였다고 해석하면 안 된다.

swap은 **00:36:35 표본**에서 120→372KiB, swap-out 63page(252KiB)가 한 번 관측됐다.
직전 표본은 00:36:30이고 마지막 부하는 00:36:31.324에 끝났다.
따라서 발생 시점은 **부하 마지막 약 1.3초와 종료 뒤 약 3.7초가 걸친 5초 구간**이며
종료 뒤 발생했다고 단정할 수 없다. swap-in은 없었고 남은 수집 동안 추가 입출력도 없었다.
진행 설명에서 재기동 뒤로 추정한 내용을 이 원시 표본 시각으로 정정한다.

부하 전 backend Metadata Full GC 4회(합계 224.988ms)와 종료 재기동 중 4회
(합계 235.829ms)는 별도다. 서버 원시 분석기의 `normalFullGcCount=3`은 readiness 이후의
준비 시간까지 포함한다. 앱 부하 시각으로 다시 자른 이번 결론은 **2회**를 사용한다.

## 8GiB 이력과 결론의 한계

[8GiB 원본 결과](api-load-ec2-8g-20260905.md)는 2,100건 전체/본 시험 1,800건 성공이다.
그때는 공공데이터와 동선 생성도 포함했다. 이번과 기능 구성·분당 요청 수·인스턴스가
다르므로 RAM만 바꾼 동일 조건 비교는 아니다.

두 시험 모두 위 항목 목표를 만족했다. 이번 일부 수치가 빨라도 4GiB가 8GiB보다 빠르다고

이번 작업의 완료 조건으로 추가하지 않는다.

## 실행 전 확인과 준비 실패 이력


로컬 오프라인 테스트 41개를 2회 실행해 모두 통과했다. HTTP 500 이후 계속 실행,
공공데이터 제외 요청 미송신, 가드 차단 뒤 외부 요청만 추가 제외, 실제 응답 내용 검증,
계정 분리·정리, 동기화 설정 복원을 포함한다. 네트워크 없는 dry run을 2회 실행한 출력도 같다.
서버에서 검증 도구 8개의 원본·수신 SHA-256을 대조했고 Python 테스트 22개를 2회 통과했다.
수집기 shell 모의 시험도 통과했다. 제품 Java/DB/Android 변경은 없다.

backend SHA `673a2f7`, graph 세대, backend/GH 힙과 메모리 상한, swap·swappiness 10,
