## 실행한 검증

- JDK 21에서 `:app:testDebugUnitTest :app:assembleRelease --no-daemon --console=plain` 실행: BUILD SUCCESSFUL, 4분 44초.
- 단위 테스트: **107클래스, @Test 866개, 실패 0·오류 0·건너뜀 0**.
- `apksigner verify --verbose --print-certs`: 성공. 생성한 신규 keystore의 인증서 SHA-256과 일치.
- APK 내부 DEX에서 staging API 주소와 현재 PC에 설정된 카카오 네이티브 앱 키의 주입을 확인했다. 실제 네이티브 키 값은 기록하지 않았다.
- DEX에 `api.runninggu.example`, `10.0.2.2`, `localhost:8080`이 없는 것을 확인했다.
- APK 메타데이터에서 패키지·버전 확인, `debuggable` 비활성 확인.

- 전달용 APK를 복사한 뒤 빌드 결과와 SHA-256 파일 해시가 같은 것을 확인했다.
- 임시 서명 비밀번호는 빌드 후 이 빌드용 `local.properties`에서 제거했다. 원래 체크아웃의 설정·소스는 변경하지 않았다.

## 건모에게 전달할 내용

이번 APK는 선경이 생성한 신규 출시 키로 서명했다. 카카오 앱의 Android 플랫폼에서 패키지 `com.runninggu.app`에 아래 키 해시를 추가한다.

```text
oRJtsESChTHqkP9fnp4lRq+wNxM=
```

기존 `FQYBObeiwECqGowYN/kOhgJc9LY=`는 민지가 기존 릴리스 키에서 추출했다고 남긴 값이다([#108 기록](https://github.com/uuusun/RunningGu/issues/108#issuecomment-5520839360)). 이전 APK나 팀원의 디버그 해시는 삭제하지 않고 새 해시를 추가한다. 콘솔 등록에는 keystore 파일·비밀번호를 전달할 필요가 없다.

등록 후 위 APK를 설치하고 다음을 실제 기기에서 확인한다.

1. 앱 실행과 staging 서버 연결.
2. 카카오 로그인: 카카오톡 설치 여부에 따른 가능한 경로, 로그인 복귀, 실패·취소 후 화면 상태.
3. 지도 표시와 관련 화면의 상호작용.
4. 전체 화면의 진입·뒤로가기·내비게이션과 로딩·빈·오류 상태.

기기·OS·APK 파일명과 해시·확인한 동작·실제 결과를 기존 릴리스 검증 기록에 남긴다. 단순히 “화면 확인함”이라고 적지 않는다. PR 스크린샷은 첨부하지 않는다.

기존 키로 설치한 앱과는 서명이 달라 덮어쓰기 설치가 실패할 수 있다. 데이터가 있는 기존 앱을 임의로 삭제하지 않고 별도 테스트 기기나 AVD를 사용한다.

## 남은 검증과 알려진 상태

- 이번 작업에서 기기에 설치하거나 카카오 로그인·지도·전체 화면을 직접 확인하지 않았다. 현재 네이티브 키가 건모가 관리하는 카카오 앱과 일치하는지, 새 해시가 등록됐는지도 기기 검증에서 확인해야 한다.
- #290 마케팅 동의 복원 PR은 확인 시점에 미머지다. 이 APK에는 해당 수정이 포함되지 않는다.
- #297 서버 공개 큐레이션 코스 상세 API PR도 확인 시점에 미머지다. 관련 화면 실패 시 서버 준비 상태를 함께 확인한다.
- 운영 서버 준비 후 같은 출시 키와 `https://api.runninggu.store/api/`로 최종 APK를 다시 만들고 검증한다.
- 생성 직후에는 외부 keystore 백업이 미완료였다. 이후 완료된 상태는 아래 후속 확인을 따른다.

## 2026-09-06 후속 확인 — 생성 당시 기록의 전제 변경

- 09-05 후속 출시 준비 기록에서 새 키의 개인 Drive 비공개 보관과 다운로드 복구 검증 완료를 확인했다. 원본과 파일 해시·인증서 일치, 실제 서명·검증 성공, 변조 메시지·잘못된 비밀번호 거부를 확인했다. 비밀번호 별도 보관은 사용자 완료 답변이 근거다. USB 백업 완료를 의미하지 않는다.

- 09-06 APK 파일 존재·크기와 SHA-256을 다시 확인했고 위 산출물 표와 일치했다.
- [#296에 산출물 식별 정보·서버 주소·시험 제약을 전달했다](https://github.com/uuusun/RunningGu/pull/296#issuecomment-5557375422). 파일 첨부·다운로드 링크 전달 완료 기록은 아직 없다.
- 현재 인프라 부하 검증이 진행 중이므로 수동 앱 시험 시간을 임의로 열지 않았다. SES는 09-05 신청, 09-06 14:27 KST 추가 정보 회신 제출까지 확인됐고 승인 완료 기록은 없다.
