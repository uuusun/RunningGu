두 실행 모두 exit 0, 14항목 전부 통과. 요청 시작 구간은 Nginx 관측상 각각
13:28:26 UTC·13:29:29 UTC이며 결과 JSON의 판정과 건수가 같았다.

| 검사 | 기대 / 실측 |

측정하지 않았다. 전체 고정 요청 세트는 아직 확정되지 않았다.

## 4. 사용자 앱 재시작 후 인증된 내 정보 조회

사용자에게 로그아웃·마케팅 스위치 조작 없이 앱 종료·재실행 후 계정 관리 진입을 요청했고,
`앱 재시작·내 정보 확인 완료`라는 응답을 받았다. 에이전트가 화면을 직접 보거나 로그인값을
추출한 것은 아니다.

- 읽기 전용 SSM: `c4b90ab0-e76a-4cbb-87a4-61191539add7`, Success / response 0.
- 확인 시각: `2026-09-04T13:30:02.232043Z`.
- EC2 current source 일치, 백엔드·GraphHopper·Docker·Nginx active.
- 직전 09:56:58 UTC 점검 이후 `GET /api/me 200` **2건**을 확인했으며,
  마지막 40개 이벤트에 13:26:21 UTC의 `/api/me 200`이 포함돼 있다.
- 같은 관측 구간에 `/me/favorites 200` 21건, `/me/courses 200` 8건, `/itineraries 200` 8건도 있었다.
  사용자 조작 등을 포함한 구간 집계이므로 이번 재시작 한 번의 호출 수로 해석하지 않는다.
- 위 네 GET의 401은 각각 2건이며 §3의 두 번의 명시적 미인증 검사와 시각이 일치한다.
- 서버 로그는 허용 경로·method·상태·시각만 집계했다. HTTP 200과 사용자 화면 표시 보고를
  확인했지만 개인정보를 포함한 응답 body 전체를 별도 검증하거나 소유권 격리까지 증명한 것은 아니다.

따라서 **인증된 GET `/me` 성공 미확인** 상태는 해소한다. 단, 이는 앱 시작 시 복원 경로이며
명시적 재로그인 직후 마케팅 표시 결함 #287의 수정·재검증은 아니다.

## 5. 두 번째 가입 확인과 남은 준비

두 번째 계정은 기존 계정 로그아웃 → 앞서 승인한 두 주소 중 아직 가입하지 않은 주소로
사용자가 비공개 비밀번호·인증 코드·약관·연령 확인을 직접 수행했고 `두 번째 가입 완료`라고 응답했다.

- 읽기 전용 SSM `ad530333-1cdb-4c89-a668-98df1e0ff139`: Success / response 0.
- 확인 시각 `2026-09-04T13:35:53.313371Z`, 같은 배포 source 유지.
- 회원 2명·인증 완료 EMAIL identity 2개. 13:30 UTC 이후 새 회원·인증 identity는 각각 1개.
- 새 회원의 TOS·PRIVACY 1.0 동의 2행, SIGNUP 인증 잔여 행 0, 활성 세션 1개.
- 13:30 UTC 이후 발송 204·인증 200·가입 201 각각 1건. 마케팅 상태는 조회·변경·재시험하지 않았다.
- DB는 READ ONLY·5초 statement timeout으로 건수만 조회했으며 주소·회원 ID·비밀값 원문을
  출력하지 않았다. 회원을 직접 삽입하거나 인증을 우회하지 않았다.

테스트 계정 2개 생성 준비는 완료됐다. 두 번째 계정의 별도 재로그인이나 두 계정 사이의
저장 데이터 접근 분리까지 확인했다는 뜻은 아니다.

두 계정 데이터 분리·제한된 쓰기, 비공개 부하 생성기 인증 입력, 외부 KTO/카카오 호출 상한과
잔여 할당량, 고정 성공 요청 세트, 실행 도구 PR 검토가 남아 있다. 계정 토큰을 DB에서 만들거나
앱에서 추출해 대신하지 않는다. 이 준비를 충족하기 전 전체 30분 부하를 시작하지 않는다.

EC2는 기존 8GiB 실행 상태다. 4GiB 변경·서버 중지·새 배포는 수행하지 않았다.
