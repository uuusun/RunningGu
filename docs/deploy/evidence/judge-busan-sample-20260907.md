## 실서버 실행 전에 남은 것

1. #305의 대회 목록/상세 계약 오류를 먼저 수정한다. 목록 응답에 좌표 필드를 새로 추가하지 않는다.
2. 위 출발지를 표본 스크립트에 반영하고 걷기 장소 enum 표기를 계약의 `PLACE`로 맞춘다.
3. 이메일 결정·계정 준비와 4GiB 시험 종료 후 서버 시험 가능 상태를 확인한다. `--dry-run`도 로그인과 실제 조회를 하므로 그 전에 실행하지 않는다.
4. 실제 `/courses/near`는 걷기 장소를 합쳐 최대 12개로 자른다. 따라서 **로컬 큐레이션 5개가 HTTP 응답 5개 또는 저장 성공 3개를 보장하지 않는다.** 실서버 응답에서 적격 ROUTE 수와 필수 저장 필드를 다시 확인한다.
5. 저장한 ID와 목록을 되읽어 저장 코스 3개·찜 3개·동선 1개가 준비됐는지 검증하고, 부족하면 부분 완료로 기록한다. 새 기기에서 해당 계정의 화면을 확인한다.

이번 완료 범위는 지역·출발지 후보 선정과 로컬 적격성 확인이다. 실제 심사 계정과 표본은 생성하지 않았다.
