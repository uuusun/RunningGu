## 실제 확인 결과

- 2026-09-05 현재 로그인된 선경 카카오 계정의 앱 목록에 런닝구가 없다. 다른 앱 설정은 열거나 바꾸지 않았다.
- #108의 최근 댓글에서 카카오 콘솔 소유자는 건모라고 확인했다. 이 댓글에 남아 있는 `FQYBObeiwECqGowYN/kOhgJc9LY=`는 민지의 이전 출시 키 해시다.
- 선경은 처음에는 등록 완료 답을 받지 못했다고 했으나, 2026-09-05 후속으로 **건모가 새 출시 키 해시 등록을 완료했다고 답했다**고 전달했다. 이는 선경의 팀원 회신 전달을 근거로 한 상태이며, 이 작업에서 건모 소유 카카오 콘솔을 직접 열어 대조한 것은 아니다. 새 앱 생성·네이티브 키 교체·기존 해시 삭제는 수행하지 않았다.
- 후속 확인에서 #104·#108·#232의 댓글에는 새 해시 등록 완료 기록이 없었지만, 이후 선경이 건모의 완료 회신을 전달했다. #104의 기존 디버그 키 확인과 이번 새 출시 키 등록은 별개다.
- APK에는 이 PC의 네이티브 앱 키가 주입돼 있다. 해당 키가 건모 콘솔의 런닝구 앱에 속하는지는 콘솔 접근 없이는 대조하지 못했다.

## 건모가 확인할 항목

### 민지의 신규 키 확인 질문에 대한 콘솔 재확인

2026-09-05 후속 읽기 전용 확인:

- 상품 `0001008828`은 판매상태 `등록중`, 목록의 검증상태는 `-`였다.
- Android 기본정보의 패키지 네임은 `com.runninggu.app`, AID는 `OA01008828`이었다.
- 신규 바이너리 메뉴는 `등록할 바이너리 유형을 선택하세요`라는 초기 화면이며 APK/AAB 라디오 모두 미선택이었다. 실제 ONE store 앱 서명 사용/미사용 옵션이 확정됐다고 보고하지 않는다.
- 이번 확인에서 유형 선택·서명 설정 변경·업로드·검증요청은 하지 않았다. 스토어 등록 작업은 사용자 결정에 따라 구현 완료 후 재개한다.
- 새로 생성한 것은 선경 PC의 자체 APK 서명용 keystore다. 원스토어에서 새 앱 서명 인증서를 발급받은 것으로 전달하지 않는다. 기존 `APK + ONE store 앱 서명 미사용` 방침을 유지한다.
- 민지가 다음 빌드를 만들 때에는 선경의 새 공식 keystore(별칭 `runninggu`)를 사용한다. 카카오 등록용 새 해시는 이 문서의 `oRJtsESChTHqkP9fnp4lRq+wNxM=`이며 기존 민지 키 해시를 새 APK의 해시로 쓰지 않는다. 기존 해시는 유지하고 새 해시를 추가 확인한다.

### APK와 카카오 대조

1. 런닝구 앱에서 현재 APK가 사용하는 **네이티브 앱 키**를 선택한다. 최신 콘솔 경로는 **앱 → 플랫폼 키 → 네이티브 앱 키**다.
2. Android 패키지가 `com.runninggu.app`인지 확인한다.
3. 기존 디버그·이전 출시 해시를 유지하면서 새 해시 `oRJtsESChTHqkP9fnp4lRq+wNxM=`가 등록돼 있는지 확인한다.
4. 등록된 같은 키의 카카오 로그인·지도 사용 설정을 확인하고 실제 새 APK로 로그인과 지도 표시를 검증한다. 콘솔 값만 일치하는 것은 기기 검증 완료가 아니다.
5. 결과를 남길 때에는 등록 여부, 사용 APK 파일명, 기기, 로그인 성공/실패, 지도 표시 여부를 적는다. 네이티브 앱 키나 비밀번호는 보고에 넣지 않는다.

2026-09-05 현재 3번의 **새 키 해시 등록은 사용자 전달 기준 완료**다. 콘솔 등록만으로 로그인·지도 검증이 완료된 것은 아니므로, 4번과 5번의 실제 서명 APK 확인은 계속 남는다.

Android 스토어 URL이 자동으로 Google Play 주소로 설정되어 있다면 원스토어 출시 방침과 맞춰 확인한다. 공식 안내상 직접 입력 또는 없음 선택이 가능하며, 원스토어 공개 URL이 생긴 뒤 해당 주소를 사용한다.
