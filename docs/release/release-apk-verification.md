## 시작 전에 갖춰야 할 것

이 셋이 없으면 시작하지 않는다. 없는 채로 debug APK 로 대신하지 않는다.

| 필요한 것 | 누가 | 상태 |

| **이메일 시험 계정/주소** — 발송 가능한 것 | 선경님 | ✅ **제약이 풀렸다 (2026-09-10)** — SES 프로덕션 승인이 안 나 **Resend 로 전환**했다(결정-62 · #321 · #327). 일반 주소의 가입 메일 수신·가입 완료는 #241, 비밀번호 재설정 전체 흐름은 2026-09-11 운영책임자 직접 확인으로 완료했다 |

> **직접 만든 debug APK 로 대체하지 않는다.** 서명이 달라 카카오 키 해시·R8 동작이 전부 달라지므로, 그 결과는 릴리스를 대신하지 못한다.

### 설치가 거부되면

기존 debug 앱과 서명이 달라 설치가 거부되면 **검증 전용 기기나 새 에뮬레이터**를 쓴다.
**기존 앱과 표본 데이터를 임의로 지우지 않는다** — 다른 검증에 쓰고 있다.

> **화면 조작을 `adb` 로 했다.** 사람이 눈으로 밟은 것이 아니라, 화면 덤프와 스크린샷을
> 떠서 판정했다. 손가락 조작에서만 드러나는 것(드래그 감각·스크롤 관성·연타)은 이 회차가
> 덮지 못한다. 순서 변경만 `input draganddrop` 으로 확인했다.

> **기존 AVD 에는 설치하지 못했다.** `INSTALL_FAILED_UPDATE_INCOMPATIBLE` — 09-02 에 깔아 둔
> 내부 개발용 키 서명 APK 와 서명이 다르다. 이 문서 「설치가 거부되면」 지침대로 **새 AVD 를
> 만들어** 설치했고, 기존 앱과 데이터는 지우지 않았다.

#### ⚠️ AVD 설정 하나가 지도를 죽인다 — 건모님도 해당

처음에 **지도가 완전히 빈 회색**이었다. 경로선도 타일도 없었다. **앱을 고치지 않고 에뮬레이터
설정만 바꿔서 정상이 됐다** — 그래서 이 AVD 의 설정 문제로 판단한다.

```
GLES: Android Emulator OpenGL ES Translator (RTX 4050) — OpenGL ES 2.0
```

호스트가 RTX 4050 인데도 에뮬레이터 GL 번역기가 **GLES 2.0** 으로 잠겨 있었다.
`~/.android/advancedFeatures.ini` 에 아래 한 줄을 넣고 에뮬레이터를 다시 켜니 **GLES 3.1** 로
올라오고 지도가 정상 표시됐다.

> **여기까지가 본 것이다.** 이 AVD 에서 GLES 2.0 일 때 회색이었고 3.1 로 올라오니 그려졌다.
> 카카오 지도 SDK 의 **공식 최소 GLES 요구사항은 확인하지 않았다** — "벡터 렌더러는 3.x 가
> 필요하다" 로 일반화하지 않는다(#318 리뷰 · 선경님). 다른 AVD·실기기에서 2.0 이면 반드시
> 같은 증상이 난다는 뜻도 아니다.

```
GLESDynamicVersion = on
```

**조용히 실패하는 것이 문제다.** `UnsatisfiedLinkError` 도 `dlopen failed` 도 **0건**이고
카카오 지도 인증(`dapi.kakao.com/v2/maps/vector/auth`)도 4번 다 `200` 이었다. 즉 **ARM 변환은
처음부터 정상**이었는데 로그에 아무 흔적이 없어서, 「지도 안 됨」을 앱 버그로 오해하기 쉽다.

선경님 AVD 는 API 37 `google_apis_playstore_ps16k` 라 기본으로 켜져 있었을 것으로 본다.
`INSTALL-WINDOWS.cmd` 안내에 이 줄을 넣으면 건모님이 같은 자리에서 안 막힌다.

부수 확인 — 지도 SDK 가 보낸 `origin/oRJtsESChTHqkP9fnp4lRq+wNxM=` 가 이 문서에 적힌
**선경님 새 출시 키 해시**와 같다. 시험본이 새 키로 서명된 것이 로그로도 확인된다.

#### Resend 비밀번호 재설정 후속 확인 — 2026-09-11 · 유선경

```
경로   실제 받은편지함에서 재설정 메일 열기 → 링크 진입 → 새 비밀번호 설정 → 새 비밀번호 로그인
실제   운영책임자가 위 전체 흐름의 성공을 직접 확인
판정   통과
```

이 항목은 운영책임자가 직접 확인한 결과를 기록한 것이다. 문서 수정 세션에서 같은 흐름을
재현하지 않았고, 사용한 앱 빌드·서버 환경 식별자는 전달받지 않았다. 이메일 주소·재설정
링크·비밀번호는 기록하지 않는다. 따라서 최종 출시 후보 서명 APK의 운영 회귀 확인은 별도로 남는다.

### 3. 지도

```
경로   S7 동선 결과 지도 · S8 러닝코스 지도
기대   타일·핀·경로선 표시
실제   **x86_64 로 설치했을 때는** 두 화면 모두 `지도를 불러오지 못했어요. 목록으로 확인해
       주세요.` 로 떨어졌다. GLES 는 3.1 로 올라와 있었으므로 1회차의 `GLESDynamicVersion`
       문제가 아니다. APK 를 열어 보니 **`libK3fAndroid.so`(카카오 지도 벡터 렌더러)가
       arm64-v8a·armeabi-v7a 에만 있고 x86·x86_64 에는 없다.** 설치된 앱이
       `primaryCpuAbi=x86_64` 라 네이티브 렌더러를 로드할 수 없었던 것이다.
       `adb install --no-incremental -r --abi arm64-v8a` 로 다시 설치해
       `primaryCpuAbi=arm64-v8a` 로 바꾸니 **바로 그려졌다.**
       S8 출발지 주변(서울시청) — 타일 정상(서울특별시청·종각역·을지로입구역·을지로3가역·
       을지로4가역·덕수궁·시청역 표기), 파란 경로선이 도로를 따라 그려지고 걷기 스팟 핀 표시.

판정   통과 — 단 arm64 변환 설치가 필요하다

> **에뮬레이터에서 지도가 죽는 원인이 회차마다 다르다.** 1회차는 GLES 2.0 이었고(#104 · AVD
> 설정), 이 회차는 **ABI** 였다. 둘 다 앱 문제가 아니지만 증상이 같아서(`지도를 불러오지
> 못했어요`) 구분이 안 된다. **x86_64 AVD 에서는 `--abi arm64-v8a` 로 설치해야 한다.**
> 실기기(arm64)에는 해당하지 않는다.

> **지도 실패가 격리되는 것은 확인됐다.** 지도가 죽어도 타임라인·목록·고도 그래프는 정상
> 표시된다(AGENTS 2장 규칙 5).

> **원인은 앱이 아니라 운영 서버다.** 같은 시각 운영 `GET /api/geocode?query=서울시청` 이
> `502 EXTERNAL_API_ERROR` 로 3회 연속 떨어지고, 스테이징 같은 요청은 `200` 이다.
> `GET /api/courses/near` 운영 응답은 `degradedSources:["KAKAO"]` 로 스스로 실패를 보고한다.
> 앱은 API 명세 §0-5 의 부분 성공 계약대로 받은 것을 그대로 그리고 있다.
> 대조표와 확인해야 할 것은 [운영 카카오 로컬 호출 실패](../deploy/evidence/production-kakao-local-20260911.md) 에 있다.

> **같은 날 해소됐다.** 운영 카카오 앱에서 카카오맵/로컬이 꺼져 있던 것이 원인이었고
> (`403 NotAuthorizedError · disabled OPEN_MAP_AND_LOCAL`), 결정-66에 따라 운영 앱을 `1442028` 로
> 바꾸고 백엔드를 재기동했다. **같은 APK(`42bfec46`)로 다시 밟아 통과를 확인했다** — 서울시청
> 프리셋에서 경로 1건 + 걷기 스팟이 거리순으로 섞여 나오고(서울광장 92m · 덕수궁 정관헌 207m ·
> 덕수궁돌담길 266m · 청계광장 287m …) `일부 정보를 불러오지 못했어요` 안내가 사라졌다.
> 서버 응답도 `degradedSources []` · `attributions ["© OpenStreetMap contributors","카카오 로컬"]`
> 로 바뀌었다. **판정을 `통과` 로 바꾸지 않고 실패 관측을 남겨 둔다** — 그 APK 로 그 시각 서버에서
> 실제로 일어난 일이기 때문이다.

> **자동 위치 파악이 없는 것을 화면에서 확인했다.** 출발지는 검색하거나 프리셋 5개에서
> 골라야 하고, 현재 위치로 잡아 주는 자리가 없다(SPEC 결정-56 · 이슈 #215).

### 9. 복구·오류

```
경로   비행기 모드 ON → 앱 강제 종료·재시작 → 홈·캘린더 → 오프라인에서 찜 → 비행기 모드 OFF

       홈 — 히어로와 마감임박은 캐시로 표시되고 `오프라인 · 09.11 18:31 기준` 안내가 붙는다(#309).
       **축제 영역만 따로 `네트워크에 연결할 수 없어요.` + `다시 시도`** 로 떨어진다 —
       영역 단위 부분 실패 격리가 화면에서 확인된다.

## 1회차에서 새로 확인한 것 — 판정과 별개

**저장 코스 상세의 경로가 실선이다.** API 명세 §7-A 는 `GET /me/courses/{id}` 를
「코스 상세 **점선** 렌더링 🔒」으로 잠가 뒀는데, 화면에서는 실선으로 그려진다. 스크린샷을
3배 확대해 끊김이 없는 것을 확인했다. 어느 쪽이 맞는지(명세를 고칠지 화면을 고칠지)는
정해야 할 일이라 이 문서에서 판정하지 않는다.

**#322 로 뗐다.** 경로선은 화면마다 따로 그리지 않고 `RunningGuMap.drawLine()` 하나를 같이
쓰는데 거기에 점선 패턴을 주는 자리가 없다 — 저장 코스만의 문제가 아니라 공통 렌더러에
점선이 구현된 적이 없는 것이다. 결정과 후속은 그 이슈에서 한다.
