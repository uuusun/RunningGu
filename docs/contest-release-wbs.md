`08-23 P0 완료`는 **코드 작성 종료**가 아니라 아래 완료 정의를 모두 충족한 상태다. 이를 충족하지 못하면 완료율을 높여 적지 말고 미완료 작업을 그대로 이월한다.

- 계약 문서와 구현이 일치하고 미정 계약이 없다.
- Android 단위 테스트·디버그 빌드, 백엔드 테스트·`bootJar`가 통과한다.
- 핵심 사용자 여정 E2E가 스테이징 환경에서 재현된다.
- 공개 PR이 `develop`에 머지됐고, 로컬 브랜치·worktree에만 있는 코드는 완료로 세지 않는다.
- 운영 설정, 오류·빈 상태, 문서와 심사 재현 절차가 함께 있다.

## 6. 위치기반서비스 신고: 대상인지부터 다시 본다

### 6.1 전제가 바뀌었다 — 신고 준비를 진행 작업으로 두지 않는다

**단말 좌표를 서버로 보내던 경로를 제품에서 없앴다**(SPEC 결정-56 · 이슈 #215). 위치 권한도
`FusedLocationProvider` 도 없고, `/api/courses/near` 에 나가는 `lat/lng` 는 사용자가 검색·프리셋·
S7 숙소로 **직접 고른 장소 좌표**뿐이다.

**다만 이것만으로 신고 의무가 없다고 단정하지 않는다.** 최종 출시 전에 실제 APK·네트워크
흐름과 갱신된 문서를 근거로 #195 에서 공식 검토 결과를 확인한다. 그 결과 신고 대상이면
아래 체크리스트를 다시 연다.

### 6.2 #195 공식 검토에 낼 증빙

- [ ] merged debug/release Manifest 에 위치·위치 FGS 권한 **0건**
- [ ] 의존성 그래프에 `play-services-location` 없음
- [ ] 앱에 위치 권한 요청·Fused Location 호출·현재 위치 UI·이동 궤적 수집 코드 없음
- [ ] 서버로 나가는 좌표가 **사용자가 고른 출발지·장소 좌표**뿐임을 보이는 데이터 흐름도
- [ ] Wi-Fi AP·기지국·BLE·IP GeoIP 로 위치를 추정하는 경로가 없음
- [ ] 개인정보처리방침 v1.2 가 위 구조와 일치
- [ ] 상담·검토 기록 보관

**신고 대상으로 판정되면** 사업자등록증·사업계획서·주요 설비·보호조치 증빙이 추가로 필요하다.
그때는 처리기간과 보완 여유를 다시 계산해 일정에 반영한다.

공식 상담 창구는 [위치정보지원센터](https://www.lbsc.kr/)(02-588-0185, `LBS@kcup.or.kr`)다. 전자 신고는 [전자민원센터 위치기반서비스사업 신고](https://www.emsit.go.kr/cp/cv/Cp1440000_0182_01Reg.do)에서 확인한다.

```text
P0 계약·구현·E2E
  └─ 운영 백엔드·개인정보/위치정보 문서
```

- **09-17까지 공개 링크가 없으면** 운영사무국에 심사 지연을 이유로 한 예외가 없음을 재확인하고, 제출 가능 여부를 사실대로 판단한다.
