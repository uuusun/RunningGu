## 이번 대화에서 확정한 결정

**선경 결정: 블록 추가 응답은 기존 `201 {blockId, orderNo}`를 유지하고 앱에서 정규화한다.**

- 이번 범위에서 서버의 추가 응답을 전체 블록으로 확장하지 않는다.
- 앱은 명세의 문자열 정규화와 추가 시 시간 기본값을 적용한 요청값 및 받은 식별자로 행을 구성한다.
- PATCH와 순서 PUT은 기존 계약대로 서버의 갱신 응답을 사용한다.
- 추가의 시간 기본값과 PATCH의 생략/null 처리는 구분한다.
- [#301 결정 댓글](https://github.com/uuusun/RunningGu/pull/301#issuecomment-5557262749)과 [#213 결정 댓글](https://github.com/uuusun/RunningGu/issues/213#issuecomment-5557262847)에 전달했다. 작성자에게 API 명세와 PR 본문을 같은 결론으로 맞추도록 요청했다.

## #300 표시 방향

현재 데이터에서 `sido="부산"`, `sigun="부산 남구"`다. **sigun만 표시하면 `부산 남구`가 된다.**
sigun이 없을 때만 sido로 대체하는 현재 PR의 표시 방향이 맞다.

남은 문제는 API 명세 §6-2·§6-4가 `sigun="남구"`라고 예시를 든다는 점이다. 현재 데이터와 표시 코드에 맞춰 sigun의 전체 지역명 의미와 예시를 같은 PR에서 보완하는 방향을 권고했다.
기존 `docs/course-bundle-contract.md`도 sigun을 시군구 표시 문자열로 정의하고 `부산 중구`를 예시로 든다. 갱신 규칙은 sido·sigun을 검증된 번들에서 보존한다. 이 근거를 기존 설명 댓글에 추가했고, 새 데이터 형식을 선택하라는 질문 대신 API 명세의 불일치를 보완하도록 요청했다.

## 검증과 한계

- 각 리뷰 등록 전에 원격 head가 검토한 커밋과 같은지 재확인했다.
- #299의 정확한 head에서 Python 테스트 22개를 두 번 실행해 모두 통과했다. 초기 실행은 의존성·임시 폴더 권한 문제로 실패했고, 기존 requests 의존성을 갖춘 임시 환경에서 재실행했다.
- #299 별도 재현: 계산값 soft=75%, paved=25%, tunnel=25%, bridge=25%, steep=50%가 CLI와 증거 JSON에서 빠지는 것을 확인했다.
- #303은 HTML 파서로 섹션 13개, 내부 앵커 누락 0개, 중복 id 0개, todo 12개, script 0개를 확인했다.
- Android/백엔드 PR은 CI와 기존 검증 기록·소스를 대조했다. 이번 리뷰에서 Gradle·기기 스모크·실제 GraphHopper 측정·원격 서버 점검·스토어 업로드는 재실행하지 않았다.
- 09-06 현재 PC의 APK 크기·SHA-256은 기존 빌드 증거와 일치했다. AWS 법인명은 실제 결제 설정 UI의 Service provider 표시로 확인했다. 결제 설정은 변경하지 않았다.
- 사용자 기존 변경은 보존했다. 제품 코드는 수정하지 않았다. 이 리뷰 기록과 APK 증거의 날짜가 표시된 후속 정정을 추가했다. 커밋·push·머지는 하지 않았다.
