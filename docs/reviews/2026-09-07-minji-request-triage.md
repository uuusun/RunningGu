## 새로 확인한 #305 실행 장애

스크립트의 `seed()`는 `GET /api/contests?size=20` 응답을 바로 `pick_contests()`에 전달한다. 그런데 이 함수가 항목의 `lat/lng` 유무로 대회를 걸러낸다.

- 실제 `ContestCardResponse`와 API 명세의 대회 목록에는 좌표가 없다. `ContestDetailResponse`에 있다.
- 실제 목록 계약 형식으로 로컬 응답을 구성하면 모든 대회가 제외되어 `좌표가 있는 대회가 목록에 없다` 오류로 종료한다. 대회 상세·코스 조회까지 도달하지 않는다.
- 기존 단위 테스트는 목록 fixture에 좌표를 추가해 둬서 16개가 두 번 모두 통과했다. 실제 API 계약 형식의 추가 재현은 실행 장애를 확인했다.
- 수정 방향: 목록 후보의 **대회 상세**를 조회해 좌표 적격성을 판정하고, 실제 목록/상세 계약을 분리한 fixture로 검증. 새 API 응답 필드를 추가할 일이 아니다.
- 재현 커밋 `34e7a873a1d79c79be53a5b6f9bd457c9e965222`, 파일 `.cache/reproduce-pr305-contest-contract.py`. 원격 호출 없이 확인했다. PR 전체 리뷰 완료를 의미하지 않는다.

`--dry-run`도 실제 로그인·GET 조회를 하고 `/courses/near`에서 OSM 생성까지 유발할 수 있다. “표본을 저장하지 않음”과 “서버에 아무 변화/부하가 없음”을 구분하고 진행 중인 4GiB 측정과 겹쳐 실행하지 않는다.

## nginx 보유 기간의 의미

nginx는 앱의 HTTP 요청을 백엔드에 전달하는 서버 앞단 프로그램이다. 서버 장애·응답 실패·접근 상황을 확인하기 위해 요청을 파일에 남길 수 있다. 현재 `backend/deploy/nginx/staging-api.conf`는 IP·시각·HTTP 방식/경로·응답 코드·크기·User-Agent를 접속 로그에 쓰고 별도 오류 로그도 지정한다.

민지의 요청은 **이 파일을 며칠 보관하고 언제 어떤 방법으로 삭제할 것인지 정해 실제 운영과 개인정보 문안을 맞춰 달라**는 뜻이다. 로그인/중복확인용 메모리 캐시의 2분 만료와 nginx 파일 로그의 보존은 별개다. 저장소에 기간이 없다는 사실만으로 실제 서버가 영구 보관 중이거나 삭제 설정이 전혀 없다고 단정하지 않는다. OS 기본 logrotate 정책이 적용되고 있는지 아직 확인해야 한다.

`logrotate`는 파일을 일정 주기로 나누고 오래된 파일을 삭제하는 운영 도구다. 실제 경로가 대상에 포함되는지, 주기·보관 개수·현재 파일까지 고려해 의도한 기간 안에 삭제되는지, 자동 실행이 정상인지 확인한다. nginx 파일을 따로 백업하거나 외부로 보내면 그 사본의 보존도 확인 대상이다. 기존 DB 백업 보존 기간을 이 로그의 기간으로 자동 대입하지 않는다.

공개 문안에는 결국 다음의 **N을 실제 정책·설정·검증 결과로 채운 문장**이 필요하다.

> 서비스 안정성과 부정 이용 대응을 위해 접속 기록을 N일간 보관한 뒤 자동 삭제합니다.

이는 설명용 틀이며 최종 법률 문안이나 보존 기간 승인안이 아니다. 보존이 필요한 항목·목적·적용 의무를 확인해 기간을 정한다. 오류·HTTP/전역 로그에 질의값이 남는 문제는 기간과 함께 확인해야 한다. 기간만 정해도 불필요한 정보 기록 문제가 해결되는 것은 아니다.
