## 남은 P2 — 완료 모드에서 실패 안내가 숨는다

`삭제 → 응답 대기 → [완료] → 네트워크 실패`를 VM에서 실행하면 `isEditing=false`,
`editError=OFFLINE`이며 원래 블록이 유지된다. 하지만 `ResultScreen.kt:488~490`의 오류와
496행의 진행 문구는 477행 `if (state.isEditing)` 안에만 있다. 완료 버튼에는 요청 중
비활성화가 없고 `onToggleEdit()`도 바로 조회 모드로 전환하므로 늦은 실패를 알리지 못한다.

진행·실패 안내를 조회/편집 공통 영역에 유지하거나, 미완료 요청의 결과를 사용자가
확인할 수 있도록 완료 전환을 처리하도록 요청했다. 날짜 탭을 막으라는 요청은 아니다.
VM 상태 경로 재현과 Compose 조건 대조 결과이며, 기기 렌더링을 실행한 결과는 아니다.

## 추가 보완 — 후보 시트 종료 조건

`ResultViewModel.kt:635`의 `editInFlight`는 이번 호출이 수락됐는지와 다르다.
시트를 연 VM에서 삭제 응답을 지연시키고 후보 선택을 호출하면 추가는 가드에서 무시되지만
기존 삭제 요청의 `editInFlight=true` 때문에 시트가 닫힌다. 검토 테스트에서 총 요청 1회,
`added=null`, `sheet=null`을 확인했다.

진행 중 추가 버튼 등은 UI가 막고 있으므로 이 VM 가드 재현을 일반 기기 조작 결과로
확대하지 않는다. 다만 기존 시트 유지 요청이 완전히 해결된 것은 아니다. 이번 요청의
수락 결과를 반환하거나 수락 경로에서만 시트를 닫도록 보완을 요청했다.

PR 본문에는 이전 873건·명세 반영 없음·204 설명이 남아 있어 현재 수정 및 댓글과
일치시키도록 요청했다. 작성자 기기 기록은 편집 진입·삭제·재조회이며, 이번 잔여 경로의
기기 관찰까지 완료된 것으로 판정하지 않았다.
