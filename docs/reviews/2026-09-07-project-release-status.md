## 1. 판정과 확인 범위

**P0의 주요 온라인 기능은 구현·통합돼 있으나, 출시 가능한 상태는 아니다.** 남은 일은 4GiB 인프라 검증뿐 아니라 저장 후 편집 UI, 오프라인 명세 잔여, 계정 버그의 기기 검증, 약관·개인정보 공개, 운영 배포와 스토어 심사다.

- 분석 전 `git fetch --prune origin`, `git pull --ff-only --autostash origin develop` 실행. `develop`을 `e8d6c5b5`에서 `398d7dbb4fd13070adfe336a8c90d60ad03e8263`로 9커밋 최신화했다.
- 기존 미커밋 수정 4파일과 미추적 출시 준비 자료는 보존했다. autostash는 충돌 없이 복원됐다.
- GitHub 열린 **이슈 13개·PR 10개**, 최신 댓글·리뷰·head·CI, 최근 종료 이슈와 머지 PR을 대조했다.
- `SPEC.md`, API 명세, 화면/API 매핑표, 출시 지침·WBS, 배포 증거, 실제 앱의 Repository 연결·Room 스키마·약관·빌드 설정과 서버 Controller를 확인했다.
- **4GiB 검증은 사용자 설명에 따라 현재 진행 중이다.** 저장소의 과거 8GiB 복구 기록을 현재 실시간 상태로 해석하지 않는다. 이번 분석에서는 EC2에 접속하거나 요청 부하·배포·재시작을 추가하지 않았다.
- 아래 담당은 기존 역할·GitHub 담당자·합의에 따른 실행 제안이다. GitHub 담당자 지정·댓글·승인·머지·이슈 종료는 수행하지 않았다.

### 3.3 P1은 출시 필수 잔여와 분리

- AP-17 카카오 전용 공유 카드, AP-18 이동시간, AP-19 이미지 고도화는 P1이다. 현재 대회 공유는 Android `ACTION_SEND`이며 카카오 공유 SDK 완료를 뜻하지 않는다. 이동시간 API/연결도 현재 운영 코드에서 확인되지 않는다. P0 이미지는 기존 데이터·placeholder·홈 사진 카드까지다.

### 6.2 결정·외부 확인과 이미 확정된 것을 구분

**새 결정 또는 외부 확인이 남은 것**

- 4GiB 검증 결과에 따른 상시 운영 사양·월 비용, 운영 전환 시점. 스테이징 월 예산을 상시 운영 승인으로 간주하지 않는다.
- nginx 파일 접속·오류 로그는 14일 보관 후 정기 삭제로 확정했고 실서버 적용·timer·권한을 확인했다. 14일 경과 뒤 실제 삭제 관찰과 이후 배포의 설정 유지 여부만 추적한다.
- #303 웹 방침 버전/시행일과 변경 고지 약속. 09-06에 사용자가 보류한 항목이다. 예시 7일/30일을 승인된 값으로 쓰지 않는다.
- Gmail 문의의 실제 국외 처리와 고지 충분성, SDK 기기 ID/성능 정보 처리, 스토어 수집정보 최종 답변.
- #195 공식 검토 담당·요청·회신, 필요 조치. 기술 제거 완료만으로 법적 적용 여부를 결론내리지 않는다.
- SES production access 승인 결과와 승인 후 일반 수신자 시험.
- 원스토어 실제 제출 폼·target API 요구·심사 소요일 확인. 심사 소요일은 확정되지 않았다.
- KTO 영속 동기화/저장이 별도 신청 대상인지에 대한 회신. 개발계정 승인·키 호출 성공은 이 확인과 다르다.
- 심사 계정 책임자·검증 일정, 공식 계정 형식·최신 제출 요구 확인.

**이미 확정돼 다시 묻지 않을 것**

- 원스토어 **APK + ONE store 앱 서명 미사용**, 패키지 `com.runninggu.app`.
- 시험 `https://staging-api.runninggu.store/api/`, 공개 운영 `https://api.runninggu.store/api/`. 주소 결정과 실제 운영 배포 완료는 다르다.
- 새 출시 키의 선경 보관·실제 서명, 민지 소스/검증 준비, 건모 카카오 콘솔·기기 검증. 옛 회사 PC 키 확보는 선행조건이 아니다.
- 새 키 외부 백업·다운로드 복구 검증 완료 기록. USB 완료까지 확대해서 읽지는 않는다.
- 운영 주체 루트메이트·공개 담당, AWS 실제 서비스 제공 법인 확인값.
- TOS 1.1·PRIVACY 1.2·MARKETING 1.1 목표, v1.0 소급 수정 금지, 외부 검토와 한 출시 단위 전환.
- #213 블록 추가 응답 유지·앱 정규화, #224 조건부 연기, 축제 자동 삽입 P0 제외.

## 8. 일정과 검증 한계

09-06 기록의 **09-11 앱 공개는 희망 목표**다. 현재 운영·약관·기기 검증·심사가 모두 남아 있어 달성을 보장할 근거는 없다. 특정 날짜를 기다려 심사를 넣기보다 준비되는 즉시 제출할 수 있도록 독립 작업을 진행해야 한다. 사용자 지시에 따른 스토어 상품 입력의 “앱 구현 완료 후 재개” 상태는 유지한다.

저장소 지침 기준 공모전 마감은 **09-21 16:00 KST**, 내부 마감은 15:00이며, 승인된 스토어 공개 링크와 공식 양식 기능설명서가 필요하다. **이번에 공식 Notion 원문과 원스토어 일부 공식 문서를 웹 도구로 재열람하려 했으나 접근/형식 오류로 최신 원문 재확인에 실패했다.** 일정·제출 요구·심사 소요일은 최종 제출 전 공지/실제 폼에서 다시 확인해야 한다. Google의 [신규 개인 계정 12명·14일 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)은 재확인했지만, 현재 원스토어 출시의 선행 작업으로 다시 넣지는 않는다.

확인한 GitHub CI:

- 최신 develop 백엔드 `398d7dbb`: [Backend build and test 성공](https://github.com/uuusun/RunningGu/actions/runs/33963612666).

- #290·#299·#300·#301의 표시된 코드 검증 성공. #278은 의도된 실패. 문서 PR의 checks 없음은 테스트 통과와 다르다.

이번 작업에서 Gradle·기기·원격 서버·실제 추천 품질·스토어 업로드 시험은 재실행하지 않았다. 제품 코드·계약·정책은 변경하지 않았고 이 분석 문서만 추가했다. 커밋·push·PR 생성·승인·머지도 하지 않았다. 최종 운영 판단은 최신 시험 증거가 채워진 뒤 내려야 한다.
