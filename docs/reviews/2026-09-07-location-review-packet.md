# #195 공식 검토용 사실관계·질문 초안

선경이 검토 요청을 준비하기 위한 자료다. 외부에 발송하지 않았으며 신고 대상 여부를 판정하지 않는다. 2026-08-25 회신이 전제한 기능과 결정-56 이후 제품을 구분한다.

## 현재 제품과 데이터 흐름

| 검토 항목 | 현재 확인된 사실 | 근거 |
|---|---|---|
| 기기 현재 위치 | 위치 권한·GPS/네트워크 자동 추정·기기 위치 전송 경로를 제품에서 제거. IP를 지역으로 변환하지 않음 | SPEC 결정-56, #218·219·220·222·215 |
| 이용자가 고른 장소 | 검색·추천 지역·여행 숙소에서 출발지를 선택. 해당 장소 좌표로 자체 서버의 주변 코스/POI 조회 | SPEC §5.8, API 명세 §6, 앱 CourseRepository |
| 외부 조회 | 앱 → 자체 백엔드 → 카카오/KTO. 서버의 장소 조회에 좌표·검색 조건을 사용. 외부 요청에 앱 회원번호·이메일·로그인 토큰을 결합하지 않는 코드 구조 | KtoPoiClient, KakaoPoiClient, CachedPoiSearchService |
| 일시 캐시 | 검색 좌표·결과가 서버 메모리 캐시 키/값에 들어감. 관련 검색 캐시는 5분 만료, 회원번호와 결합하지 않음 | API 명세·캐시 구현, PRIVACY 1.2 초안 |
| 저장 코스 | 사용자가 저장하면 생성/선택한 코스 경로와 출발지 좌표를 회원 데이터로 보관. 실제로 달린 이동 기록이 아님 | SPEC 결정-33·56, savedcourse 구현 |
| 저장 여행 동선 | 사용자가 저장한 동선의 장소 블록·숙소 좌표도 회원 데이터로 보관 | ItineraryPersistenceService, ItineraryBlock |
| 삭제 | 사용자의 코스/동선 삭제·회원 탈퇴 시 해당 저장 데이터 삭제 | API 명세, 회원 탈퇴·저장 API 구현. 최종 기기 검증 #241 잔여 |
| IP | 로그인·중복 확인 남용 제한용 메모리 처리뿐 아니라 nginx 파일 접속 로그에도 기록 | staging-api.conf, #303·304 기술 리뷰 |
| 오류 로그 | HTTPS access_log는 질의 문자열을 제외하지만 error_log·HTTP/전역 설정까지 제외됐다고 단정할 수 없음 | 아래 미확인 항목 |

카카오 네이티브 SDK의 지도·로그인 통신 전체를 네트워크 캡처로 검증한 자료는 아직 없다. 자체 서버 REST 경로에 대한 확인을 SDK 전체의 수집정보 검증으로 확대하지 않는다.

## 문의 초안

루트메이트는 Android 앱 런닝구(區)를 개발하고 있습니다. 2026-08-25 문의 이후 제품을 변경하여 기기의 현재 위치 자동 추정과 GPS 이동 기록을 모두 제외했습니다. 이용자는 직접 검색한 장소·추천 지역·숙소를 출발지로 선택합니다. 선택 장소 좌표는 주변 관광 장소·러닝코스 조회에 이용하고, 사용자가 저장한 코스와 여행 동선의 장소·숙소 좌표는 회원 데이터로 보관합니다. IP는 보안상 요청 횟수 제한과 서버 접속 로그에 쓰며 위치로 변환하지 않습니다.

현재 구조를 기준으로 다음 항목의 검토 경로와 필요한 자료를 안내받고자 합니다.

1. 이용자가 직접 선택한 장소의 좌표로 주변을 검색하는 기능에 적용되는 위치정보 관련 신고·동의 의무가 있는지.
2. 실제 이동 기록이 아닌 추천 코스 경로와 여행 장소·숙소 좌표를 이용자가 저장한 회원 콘텐츠로 보관하는 경우 추가로 구분해야 할 사항이 있는지.
3. 위치로 변환하지 않는 요청 IP의 보안 처리·접속 기록을 위 기능과 함께 검토할 때 필요한 설명과 자료는 무엇인지.
4. 적용 대상에 해당하면 운영 주체 루트메이트가 공개 출시 전에 밟아야 할 절차, 별도 약관/동의·확인자료 보존의 정확한 대상과 확정 근거를 어디에서 확인해야 하는지.

## 보완한 뒤 제출할 것

- [ ] 최종 공개 대상 APK의 파일 해시·서명·소스/서버 커밋. 현재 [#290 시험 APK](../deploy/evidence/staging-apk-pr290-49b621ed-20260907.md)는 기술 확인용이며 최종 제출본이 아님.
- [ ] 실제 기기에서 검색·추천 지역·숙소 선택·저장·삭제를 관찰한 기록 및 민감정보를 제외한 통신 경로 도식.
- [ ] SDK 자체 수집정보와 처리 주체·국외 처리의 공식 근거 대조.
- [ ] nginx 정상·오류·HTTP 리다이렉트·전역 로그의 기록 항목 및 보유/삭제 설정. 실제 사용자의 질의나 토큰으로 시험하지 않음.
- [ ] #303·304 기술 정정 후 최종 개인정보 문안. 미정 기간·시행일은 이번 초안에서 채우지 않음.
- [ ] 공식 검토 요청 담당·발송 기록·회신·그에 따른 출시 판단을 #195 및 #225에 연결.

## nginx 확인 근거

`backend/deploy/nginx/staging-api.conf`의 사용자 지정 형식은 HTTPS access_log에 적용된다. 29행의 error_log warn에는 별도 형식이 없다. nginx의 요청 오류 처리기는 원래 요청행과 upstream URI를 기록할 수 있다([공식 소스](https://github.com/nginx/nginx/blob/master/src/http/ngx_http_request.c#L3891-L3955), [error_log 문서](https://nginx.org/en/docs/ngx_core_module.html#error_log)). 이는 저장소 설정과 공식 구현에 근거한 점검 항목이며 실제 서버 로그의 유출을 확인한 결과는 아니다. 진행 중인 4GiB 시험 서버는 조회·변경하지 않았다.
