# 약관·동의 문안

A2 회원가입에서 사용자에게 보여주는 문안이다. 서버가 `USER_AGREEMENT` 에 저장하는
**버전과 여기 문안이 1:1로 대응해야 한다** — 서버는 `1.0` 을 저장하는데 앱이 보여준 게
다른 글이면 동의 이력이 무엇에 대한 동의인지 알 수 없다(NFR-12).

> ## ⚠️ 이 문서들은 **법률 검토를 받지 않은 초안**이다
>
> 개발자가 **제품이 실제로 무엇을 수집하고 무엇을 하는지**를 기준으로 적었다. 문장이
> 사실과 맞는지는 코드·SPEC 과 대조해 확인할 수 있지만, **법적으로 충분한지는 확인하지
> 않았다.** 공모전 제출·실제 배포 전에 아래를 받아야 한다.
>
> - 개인정보 수집·이용 동의의 법정 고지 항목 충족 여부 (개인정보 보호법 §15·§22)
> - 보유·이용 기간과 파기 절차의 적정성
> - 만 14세 미만 가입 처리 — **현재 제품에 연령 확인이 없다**(아래 미결 참고)
> - 마케팅 수신 동의의 표시 의무 (정보통신망법 §50)
> - **위치정보법** 검토 — 러닝코스는 **이용자가 검색하거나 눌러서 고른 장소**의 좌표를
>   서버로 보내 결과를 받는다. **기기·네트워크 신호로 현재 위치를 자동 추정하는 경로는
>   전부 없앴다**(#215 — GPS · Wi-Fi AP · Cell-ID · BLE · IP 지오로케이션). 고른 장소의
>   좌표도 위치기반 서비스로 볼지 확인해야 한다 (#133 리뷰 · #111)
> - **남용 방지 목적의 IP 처리** — 중복 확인 rate limit 이 IP 를 서버 메모리에 두고,
>   마지막 사용 후 2분에 만료되며 이후 캐시 유지보수 시 제거된다. 별도 동의가 필요한지,
>   지금 문안으로 고지가 충분한지 (#133 리뷰)

## 버전 규칙

- 디렉터리 이름이 곧 버전이다. `v1.0/` ↔ 서버 `runninggu.auth.agreements.*-version: "1.0"`
- **문안을 고치면 버전을 올린다.** 오타 수정도 마찬가지다 — 같은 버전에 다른 글이 있으면
  이력이 가리키는 대상이 흔들린다
- **이미 나간 버전의 파일은 고치지 않는다.** 서버가 그 버전으로 저장한 동의 이력이
  가리키는 글이라, 나중에 손대면 "무엇에 동의했는가" 가 달라진다

### 문안을 쓰는 것과 그 버전을 켜는 것은 다른 일이다

새 버전 디렉터리를 **추가하는 PR** 과 서버의 활성 버전을 **올리는 PR** 은 나눈다. 문안이
먼저 있어야 검토할 수 있는데, 검토가 끝나기 전에 서버만 올리면 **앱은 옛 글을 보여주고
서버는 새 버전으로 이력을 남긴다.**

**`v1.2` 는 코드보다 앞서 있다.** 문안이 "위치 권한을 선언하지도 않습니다" 라고 단언하는데,
`develop` 에는 `ACCESS_FINE_LOCATION`·`ACCESS_COARSE_LOCATION` 과 `play-services-location`,
`FusedLocationProvider` 가 아직 있다. **#215 의 권한·의존성·기기 위치 계층 제거가 머지되기
전에는 켜지 않는다** — 켜는 순간 문안이 거짓이 된다(#217 리뷰).

활성 버전을 올릴 때는 아래 넷을 **같은 PR 에서** 맞춘다.

1. 서버 `runninggu.auth.agreements.{type}-version`
2. 앱 `AgreementDoc.{TYPE}.version` — **약관마다 따로 든다.** 서버가 셋을 각각 관리하고
   지금은 `v1.1/privacy.md` 만 있어서, 묶어 두면 PRIVACY 를 올릴 때 없는 `v1.1/tos.md` 를
   읽어 두 문안이 안 열린다(#191 리뷰)
3. 그 버전 폴더에 **해당 파일이 실제로 있는지** — `AgreementTextsTest` 가 막는다
4. 위 표의 "서버 활성" 열

### ⚠️ · 🔄 블록은 켜기 전에 걷는다

문안 안의 `⚠️ 미결` · `🔄 리뷰 중` 블록과 **이슈·PR 번호**는 팀이 읽는 초안 표시다.
사용자에게 그대로 나가면 **약관에 내부 진행 상황이 실린다.** 활성 버전을 올리는 PR 에서
지우거나 확정 문장으로 바꾼다.

지울 수 없으면 **아직 켤 때가 아니라는 뜻**이다 — 미결이 남았다는 말이니까(#217 리뷰).

> 지금 `v1.2/privacy.md` 가 ⏸ 인 이유다 — 문안은 있고, A2 연결과 서버 전환은 아직이다.
> 이 순서는 #111 에서 합의했다.
>
> **`v1.1` 은 한 번도 켜지 않은 채로 끝났다.** 검토가 끝나기 전에 기기 위치 기능이
> 없어져서(#215) 문안이 사실과 어긋났다. **이미 나간 버전이 아니므로 고치지 않고 새
> 버전을 뒀다** — 위 "버전 규칙" 을 그대로 따른 것이고, 서버가 `1.1` 로 저장한 동의
> 이력은 하나도 없다. 파일은 무엇이 왜 달라졌는지 대조할 수 있게 남긴다.

## 어디에 두고 어떻게 보여줄 것인가 — **이 폴더를 앱에 번들한다** (#191)

A2 동의 단계의 각 줄에 [보기] 가 있고, 누르면 전문이 뜬다. 앱은 **이 폴더의 파일을 그대로**
읽는다 — `android/app/build.gradle.kts` 가 여기를 assets 소스로 물려 둔다.

```kotlin
assets.srcDir(rootProject.file("../docs/agreements"))
```

`docs/agreements/v1.0/tos.md` → assets 의 `v1.0/tos.md`. **사본이 없으므로 드리프트할 자리가
없다.** 앱이 보여준 글과 서버가 저장한 버전이 어긋나면 동의 이력이 무엇에 대한 것인지 알 수
없다(NFR-12)는 것이 이 방식을 고른 이유다.

- 읽는 쪽은 `data/local/AgreementTexts` · `AgreementDoc`
- 마크다운 **기호만** 걷어 낸다(`AgreementMarkdown`). 문장은 안 바꾼다
- `README.md`(이 파일)는 팀 내부 문서라 `ignoreAssetsPatterns` 로 APK 에서 뺀다

### 서버가 본문을 주게 되면

아래 A 안이 여전히 낫다. **그때 바뀌는 것은 `AgreementTexts.load` 하나**이고 화면은 그대로다.

| 안 | 방식 | 평가 |
|---|---|---|
| **A** | 서버가 `GET /api/agreements/{type}` 로 본문 제공 | 버전과 문안이 한 곳. 앱 배포 없이 개정 가능 |
| B | 서버가 웹 페이지로 서빙 + Custom Tabs | 서버가 이미 재설정 페이지를 서빙(§4.3). `androidx.browser` 새 의존성 |
| ~~C~~ | ~~앱에 문자열로 박기~~ | 버전과 문안이 갈라진다. **번들은 이것과 다르다** — 원본 파일을 그대로 싣는다 |

지금 방식은 앱 배포 없이 문안을 고칠 수 없다는 점에서 A 보다 약하다. 다만 **P0 에서는 문안을
고치면 어차피 서버 활성 버전도 함께 올려야 하므로**(아래 절차) 앱 배포가 한 번 더 드는 것이
전부다.

## 남은 결정

### 문안을 배포하기 전에 **구현이 따라와야 하는 것**

문안이 약속하는데 아직 없는 기능이다. 이대로 배포하면 문서와 제품이 어긋난다.

| # | 내용 | 무엇이 없나 |
|---|---|---|
| **A** | **만료된 인증·세션 기록의 삭제 주기** | 서버에 정리 작업이 없다(`@Scheduled` 0건). 유효시간(10분·30분)이 지나도 행이 남고, **가입까지 안 간 이메일 주소도 남는다** — 탈퇴로도 안 지워진다 |
| **B** | 마케팅 수신 끄기 | `PATCH /me/agreements` 는 **섰다**(#151) 앱 연결도 끝났다(#164). 남은 것은 **메일 수신거부 링크** 뿐이다 |
| ~~**C**~~ | 내 정보 보기·고치기·**탈퇴** | 보기·고치기는 `GET`·`PATCH /me`(#151 · 앱 #164). **탈퇴 서버가 섰다** — `POST /me/reauth` · `DELETE /me`(#198). 앱은 리뷰 중(#212) |
| ~~**D**~~ | 비밀번호 변경 | **끝났다** — 서버 `PUT /me/password`(#194) · 앱(#200) |

**A 만 남았다 — 제일 무겁다.** 보유 기간을 못 적으면 개인정보 문서가 성립하지 않는다.
B 는 메일 수신거부 링크, C 는 앱 탈퇴 화면(#212 머지)만 남았다.

현재 구현된 엔드포인트다 (2026-08-27 기준).

```
/api/auth       signup · login · refresh · logout
                email/exists · email/send-code · email/verify · nickname/exists
/api/me         GET · PATCH · PATCH /agreements                       (#151)
                PUT /password                                         (#194)
                POST /reauth · DELETE /me                             (#198)
/api/me/courses POST · GET · GET /{id} · DELETE /{id}                 (#152)
/api/me/favorites GET · PUT /{id} · DELETE /{id}                      (#150)
```

**세 엔드포인트가 다 섰다.** 예전에 "아직 없는 것" 으로 적어 둔 `PUT /me/password` ·
`POST /me/reauth` · `DELETE /me` 다. 남은 것은 서버가 아니라 **삭제 주기(A)** 와
**앱 탈퇴 화면(#212)** 이다.

### 문안에 적을 값이 **정해져야 하는 것**

| # | 내용 | 왜 지금 정해야 하나 |
|---|---|---|
| 1 | **만 14세 미만** 가입을 어떻게 할 것인가 | 현재 A2 에 연령 확인이 없다. 법정대리인 동의를 받을 수 없으면 "만 14세 이상만 가입" 을 약관에 넣고 가입 시 확인해야 한다 |
| 2 | 사업자·운영 주체 표기 | 팀 프로젝트라 사업자가 없다. 공모전 제출본에서 무엇으로 적을지 |
| 3 | 개인정보 보호책임자 연락처 | 위와 같음 |
| 4 | 처리 위탁 업체 | 이메일 발송 서비스·배포처(클라우드)가 정해지면 업체명이 들어가야 한다 |
| 5 | 관심 지역 기준 발송 여부 | 지금 제품은 관심 지역을 수집하지 않는다. 찜한 대회의 지역을 쓰려면 이용 항목에 적어야 한다 |

1번이 제일 급하다 — 화면 흐름이 바뀐다.

> **이 다섯은 #215(GPS 제거)에서 건드리지 않았다.** 운영 주체·연락처처럼 **사람이 정해야
> 하는 값**이라, 제품에서 기능 하나가 빠졌다고 답이 나오지 않는다. v1.2 는 **이미
> 구현·계약으로 확정된 사실만** 반영했다 (#111 합의).
