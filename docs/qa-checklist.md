# 런닝구 QA 체크리스트

> **무엇** — 출시 후보 APK 를 사람이 손으로 돌려 보는 항목표. 단위·계측 테스트가 못 보는 것(화면 사이 흐름 · 실제 서버 · 지도 · 문구)을 본다.
> **기준** — `SPEC.md` §2~§4 · `docs/screen-api-matrix.md`. 항목마다 근거 절을 적었으니 기대 결과가 의심되면 그 절을 본다. **문서가 이긴다.**
> **회차 기록** — 맨 아래 "실행 기록" 에 날짜 · 빌드 · 기기 · 결과를 남긴다. 결과 칸은 ✅ 통과 · ❌ 실패(이슈 번호) · ⏭ 건너뜀(이유) · ➖ 해당 없음.

### 기기·빌드 준비

- **AVD** — `runninggu_qa_arm`(API 30 · arm64 변환). 카카오 지도 SDK 가 arm64 전용이라 x86 AVD 에선 지도가 안 뜬다. 설치는 반드시 `adb install --abi arm64-v8a`.
- **디버그 빌드는 `10.0.2.2:8080`** 을 본다. 서버 없이 실데이터를 보려면 호스트 8080 에 스테이징 릴레이(`docs/agent-reference.md` 3장)를 띄운다.
- **릴리스 서명 빌드** 는 `local.properties` 의 `API_BASE_URL` 을 본다. 카카오 로그인·지도는 서명 키 해시가 콘솔에 등록된 빌드에서만 된다(#108).
- **계정** — QA 전용 이메일 계정 1개(가입 흐름에서 만든다) + 카카오 테스트 계정 1개(실기기).
- **네트워크 끊기** — 에뮬레이터는 `adb shell svc wifi disable && adb shell svc data disable`, 복구는 `enable`.

### 서버 쪽 준비가 필요한 항목

아래는 앱만으로는 못 만든다. **스테이징 DB** 에서 만들고, 운영엔 손대지 않는다. 담당은 백엔드(선경).

| 필요한 상태 | 만드는 법 | 쓰는 항목 |
|---|---|---|
| `active=false` 대회 | 먼저 그 대회를 찜·동선 저장해 둔 뒤 `UPDATE contest SET active=false WHERE id=…` | F-08 · J-05 · H-21 |
| 대회 날짜가 바뀐 저장 동선 | 동선 저장 뒤 그 대회의 `event_date` 를 하루 미룸 | H-20 |

| 세션 만료 | `refresh_token` 행 revoke 또는 삭제 | A-04 · B-21 |
| 특정 API 만 실패 | 스테이징 릴레이(`relay.py`)에 경로별 500 반환 옵션을 두면 서버를 안 건드려도 된다 | D-07 · E-14 · F-07 · G-12 · I-14 · J-14 |
