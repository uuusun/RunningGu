## 근거와 확인 범위

- [원스토어 수집정보 공식 안내](https://onestore-dev.gitbook.io/dev/docs/apps/product/common-info/main-info/data)를 브라우저로 읽었다. 개인정보 수집 시 방침 URL이 필요하며, 위치정보는 사용자 또는 기기의 실제 물리적 위치로 설명한다. 일시적 실시간 메모리 처리의 예외도 안내한다.
- `SPEC.md` 결정-56, `docs/agreements/v1.2/privacy.md`, Android 의존성과 앱/서버 소스의 수집 관련 경로를 읽었다. 개인정보 문안 1.2는 아직 법률 검토 전 초안이다.
- 기준 로컬 체크아웃은 `e8d6c5b5`, 앞서 만든 서명 staging APK의 소스는 `375b6077`이다. 이번에 최종 APK의 실제 통신을 캡처한 것은 아니다.
- Gradle 캐시에 있는 카카오 로그인 SDK 2.21.1과 지도 SDK 2.12.8을 정적으로 확인했다. 로그인 SDK의 `Utility.androidId`는 `ApplicationContextInfo.mSalt`를 만드는 경로로 확인했다. 메서드가 존재한다는 이유만으로 기기 ID의 외부 전송을 단정하지 않는다.
- 지도·로그인 SDK의 요청 헤더에는 기기 모델·OS·앱 패키지 등의 정보가 포함된다. 이 정보만으로 개인 기기를 식별하는 ID 전송 여부나 원스토어의 성능 정보 분류를 확정하지 않았다. 지도 네이티브 라이브러리 전체 동작은 이번 확인 대상에 포함하지 못했다.
- [Google 개인정보처리방침](https://policies.google.com/privacy?hl=ko)은 전 세계 서버 처리를 안내한다. `privacy.md`에는 Gmail 문의의 국외 처리 계획이 있다. AWS 서울 리전만으로 서비스 전체의 국외 이전 없음을 증명할 수 없다.
- 저장소 nginx 설정은 접속 IP·User-Agent 로그를 정의한다. 실제 운영 배포 구성과 보유 정책도 최종 개인정보 선언·방침을 확정할 때 대조해야 한다. 부하 검증 중인 EC2에는 이번 작업으로 접속하거나 변경하지 않았다.

## 남은 확인

1. 최종 APK에 포함된 카카오 SDK의 실제 수집·전송·보관 항목을 확인하고 기기 ID/성능 정보의 답을 확정한다.
2. Gmail 고객 문의를 포함한 선언 범위와 실제 국외 처리 구성을 확인한다. 필요하면 원스토어에 문의할 초안을 준비하며, 사용자 승인 없이 문의를 발송하지 않는다.
3. 공개 개인정보처리방침 URL과 최종 활성 약관을 맞춘 뒤 콘솔의 최종 수집정보를 저장한다.
