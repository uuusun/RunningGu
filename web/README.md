# 웹 페이지 (`runninggu.store`)

스토어 등록에 필요한 공개 페이지다. **빌드 도구가 없다** — 정적 HTML 파일 그대로 올린다.

| 파일 | 주소 | 왜 필요한가 |
|---|---|---|
| [`privacy/index.html`](privacy/index.html) | `runninggu.store/privacy/` | **원스토어 앱 등록 필수** — 개인정보를 수집하는 앱은 처리방침 URL 을 함께 등록해야 한다 |

배포와 도메인 연결은 유선경 담당이다.

### 계정 삭제 페이지는 아직 없다

원스토어 개발자센터 문서의 **앱 등록 입력란에 계정·데이터 삭제 URL 항목이 없다.**
Google Play 는 계정 생성이 있는 앱에 앱 내 + 웹 삭제 요청 경로를 요구하므로 **Play 전환
시 필요해진다.**

> **"입력란이 없다" 와 "삭제 요청 경로가 필요 없다" 는 다른 말이다.** 앱 안의 회원 탈퇴
> 기능은 지금도 제공하며, 처리방침 8장에 그 경로를 적어 뒀다. 여기서 정리한 것은
> **별도 웹 페이지를 이번 출시 범위에 넣지 않는다**는 것뿐이다.
>
> 실제 등록 폼에 항목이 있는지는 콘솔 접근이 있는 유선경이 확인한다.

## 이 페이지는 `docs/agreements` 와 다른 문서다

같은 내용을 다루지만 **법적 성격이 다르다.** 한쪽을 고쳤다고 다른 쪽이 따라 바뀌지 않는다.

| | `docs/agreements`의 활성 개인정보 동의문 | `web/privacy/index.html` |
|---|---|---|
| 무엇 | **개인정보 수집·이용 동의서** | **개인정보처리방침** |
| 근거 | 개인정보 보호법 §15 · §22 (동의) | 개인정보 보호법 §30 (공개 의무) |
| 어디에 | 앱 A2 가입 화면 | 웹 · 스토어 등록 URL |
| 누가 보나 | 가입하는 사람이 동의하기 전에 | 누구나, 가입하지 않아도 |
| 버전 | 서버 `USER_AGREEMENT` 와 1:1 대응 (NFR-12) | 시행일로 관리. 동의 이력과 무관 |

**처리방침에만 있는 항목**이 있다 — 동의서에는 없어도 되지만 처리방침에는 §30 상 있어야 한다.

- 개인정보 파기 절차·방법 (7장)
- 자동 수집 장치의 설치·운영 및 거부 (10장)
- 개인정보 보호책임자 (11장)
- 권익침해 구제방법 (12장)
- 처리방침의 변경 (13장)

그래서 이 페이지는 동의서를 **그대로 옮긴 것이 아니라** §30 형식에 맞춰 재구성하고
위 다섯 장을 더한 것이다. 사실관계(수집 항목·보유 기간·수탁자)는 활성 동의문과 맞추고,
활성 문안을 고칠 수 없으면 다음 버전 문안을 새로 만든다.

### 고칠 때

**사실관계가 바뀌면 두 문서를 같이 고친다.** 수집 항목·보유 기간·수탁자·좌표 처리 방식이
여기 해당한다. 한쪽만 고치면 "가입할 때 본 글" 과 "공개된 방침" 이 어긋난다.

`docs/agreements` 쪽은 **버전을 올려야 하고 이미 나간 버전은 고치지 않는다**(README 참고).
이 페이지는 시행일과 13장 변경 이력을 갱신한다.

## 공개본 1.0

`privacy/index.html`은 2026-09-13 공개용 웹 버전 1.0이다. 앱 출시 전에 공개한 후보 문안을
실제 처리 흐름에 맞게 최종 교정했으며, 이 작성 과정은 Git 이력으로 관리한다. 웹 버전은 앱
가입 동의의 `PRIVACY` 버전과 공유하지 않는다.

웹 1.0 최종본은 카카오 콘솔의 실제 동의항목을 대조해 카카오가 제공하는 개인정보를 회원번호로
바로잡고, 처리 근거·외부 API 연동·처리위탁·국외 이전 근거와 안전성 확보 조치를 명확히 한다.
같은 사실관계는 기존 활성 `PRIVACY 1.2`를 고치지 않고 다음 `PRIVACY 1.3` 초안에 반영한다.

확정한 운영 약속과 사실관계는 다음과 같다.

| 값 | 확정 |
|---|---|
| 웹 처리방침 버전 | `1.0` |
| 최초 시행일 | `2026-09-13` — 실제 HTTPS 공개일 |
| 변경 고지 | 일반 변경 7일 전, 이용자에게 불리한 변경 30일 전 |
| 운영 주체 | `루트메이트` — #230 |
| 개인정보 보호·고충처리 담당 | `루트메이트 개인정보보호 담당` — #230 |
| 문의 주소 | `runninggu.play@gmail.com` — #230 |
| AWS 수탁 법인명 | `Amazon Web Services Korea LLC` — 2026-09-06 AWS Billing 확인 (#230) |
| 메일 발송 수탁자 | `Plus Five Five, Inc. (Resend)` — Resend DPA·스테이징 전환 확인 (#321) |
| Resend 국외 처리 | 이메일 데이터·기록은 미국에 저장, 일반 요금제 기준 30일 보유 |
| 서버 접속 파일 로그 보관 | **14일 보관 후 정기 삭제** — SPEC 결정-61 · #313 |
| 앱 API HTTP·HTTPS 접속 기록 | 두 연결 모두 질의 문자열 제외 — [2026-09-07 적용 기록](../docs/deploy/evidence/nginx-log-location-audit-20260907.md) |

| 카카오 로그인 제공 항목 | 카카오 회원번호. 닉네임은 런닝구에서 직접 입력하고 카카오 프로필·이메일은 받지 않음 |
| 국외 이전 근거 | 개인정보 보호법 제28조의8 제1항 제3호 가목에 따른 계약 이행 목적의 처리위탁·보관 |
| 재위탁 | 운영팀이 확인한 범위에서 별도로 공개할 재수탁자 없음 |
| 서버 로그 보호 | HTTP·HTTPS·알 수 없는 Host의 최소 접속 로그에 요청 경로·질의 문자열·Host·User-Agent를 남기지 않고, 요청 원문을 부분 제외할 수 없는 nginx 요청 처리 오류 로그는 파일에 저장하지 않음 — [실서버 검증](../docs/deploy/evidence/server-log-privacy-staging-production-20260910.md) |

외부 법률 검토는 완료했다고 표시하지 않는다. 실제 처리 주체·수탁자·보유 기간 또는 Gmail
사용 여부가 바뀌면 이 문서의 고칠 때 절에 따라 공개본과 다음 앱 동의 버전을 함께 검토한다.

### 공개 검증

```bash
grep -Ec 'noindex|class="(draft|todo)"|\[확인 필요\]' web/privacy/index.html
grep -c '버전 1.0' web/privacy/index.html
grep -c '시행일 2026-09-13' web/privacy/index.html
curl --head https://runninggu.store/
curl --head https://runninggu.store/privacy/
```

첫 명령은 `0`, 다음 두 명령은 각각 `1`이어야 한다. 배포 뒤 루트는 `/privacy/`로 `302`,
처리방침은 인증 없이 `200`이어야 한다.

## `⚠️` 를 쓰지 않는다

`⚠️` 는 **팀 내부 검토 표기로 예약**돼 있다(#265). 이 페이지는 사용자에게 보이는 글이므로
주의 문구가 필요하면 기호가 아니라 문장으로 쓴다. `docs/agreements` 의 활성 문안에는
`AgreementPublishGuardTest`(#278)가 이 규칙을 강제하지만, **이 디렉터리는 그 가드 밖이다.**

## 확인

브라우저로 파일을 직접 열면 된다. 서버가 필요 없다.

```bash
open web/privacy/index.html
```

폰트는 Pretendard 를 먼저 찾고 없으면 시스템 폰트로 물러선다 — 웹폰트를 받아오지 않으므로
네트워크 없이도 같은 모양이다.
