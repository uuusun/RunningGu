루트메이트(이하 “운영팀”)는 런닝구(區) 서비스(이하 “서비스”)를 운영하면서 이용자의 개인정보를 소중히 다루며, 「개인정보 보호법」 등 관계 법령을 준수합니다. 운영팀이 어떤 개인정보를 어떤 목적으로 처리하는지, 얼마나 보관하고 어떻게 파기하는지를 아래와 같이 알려드립니다.

서비스는 기기의 위치를 수집하지 않습니다. 앱은 위치 권한을 요청하지 않으며, GPS·Wi-Fi·이동통신 기지국·블루투스·IP 주소 등 어떤 방법으로도 이용자가 지금 어디에 있는지를 자동으로 알아내지 않습니다. 러닝코스와 여행 동선은 이용자가 직접 검색하거나 눌러서 고른 장소의 좌표만으로 찾습니다. 자세한 내용은 2. 처리하는 개인정보의 항목에 적었습니다.

1. 개인정보의 처리 목적과 법적 근거

운영팀은 아래 목적과 근거에 따라 필요한 범위에서만 개인정보를 처리합니다.

개인정보를 원래 목적과 합리적으로 관련된 범위 밖에서 이용하거나 별도의 동의가 필요한 방식으로 처리 목적을 변경하는 경우에는 사전에 알리고 필요한 동의를 받습니다.

2. 처리하는 개인정보의 항목

가입할 때

가입 방식항목

카카오카카오 회원번호, 이용자가 런닝구에 직접 입력한 닉네임
공통만 14세 이상 확인값, 약관 동의 항목·버전·시각, 선택적 마케팅 수신 동의 상태

현재 카카오 로그인에서 카카오가 런닝구에 제공하는 개인정보는 카카오 회원번호입니다. 닉네임은 이용자가 런닝구 가입 화면에서 직접 입력합니다. 런닝구는 카카오로부터 프로필 닉네임, 프로필 이미지, 이메일 주소, 이름, 성별, 연령대, 생일, 출생연도 또는 전화번호를 제공받지 않습니다. 카카오 로그인 화면에 계정 이메일이 표시될 수 있으나 해당 이메일은 런닝구에 전달되지 않습니다.

만 14세 이상 확인은 가입 화면의 별도 필수 항목입니다. 약관 전체 동의로 자동 선택되지 않으며, 확인하지 않으면 가입할 수 없습니다. 이 확인값은 가입 요청을 검증할 때만 사용하고 생년월일이나 실제 나이는 수집하지 않습니다. 별도의 연령 값을 저장하지 않으며, 가입이 완료되면 동의한 이용약관의 버전과 시각만 기록합니다.

비밀번호는 원문으로 보관하지 않습니다. 되돌릴 수 없는 값(BCrypt 해시)으로 바꿔 저장하며, 운영팀도 원래 비밀번호를 알 수 없습니다.

IP 주소 — 두 가지가 서로 다릅니다

IP 주소가 남는 자리가 둘이고 성격이 다릅니다. 나눠서 설명합니다.

① 요청 횟수를 세는 데 쓰는 IP — 서버 메모리에만

두 자리에서 접속한 IP 주소를 요청 횟수를 세는 데만 사용합니다.

언제무엇을 막기 위해한도
로그인할 때다른 사람의 비밀번호를 반복해서 시도하는 것1분에 30회
가입 화면에서 중복 확인을 누를 때가입된 이메일·닉네임을 알아내려는 시도1분에 30회
  • 데이터베이스에 저장하지 않습니다. 서버 메모리에만 둡니다.
  • 마지막 사용 후 2분이 지나면 만료되어 더는 사용되지 않으며, 이후 메모리 정리 시점에 제거됩니다.
  • 요청 횟수 외의 용도로 사용하지 않고, 회원 정보와 연결해 보관하지도 않습니다.
  • IP 주소로 지역을 알아내지 않습니다. 지역·좌표로 변환하는 조회를 사용하지 않으며 추천·검색·개인화에도 쓰지 않습니다.
  • 확인하려는 이메일·닉네임 자체는 되돌릴 수 없는 값(SHA-256)으로 바꿔 계산합니다.
  • 로그인은 IP 와 별개로 이메일 주소로도 횟수를 셉니다(1분에 5회). 이 값 역시 서버 메모리에만 두고 저장하지 않습니다.

② 서버 접속 기록 — 파일로 남습니다

서버 앞단(리버스 프록시)이 모든 요청의 접속 기록을 서버의 로그 파일에 남깁니다. 장애를 확인하고 공격을 파악하기 위한 일반적인 서버 운영 기록입니다.

남는 것예
접속한 IP 주소
접속 시각
허용된 요청 방식 분류GET · POST · 그 밖의 방식
응답 상태 코드·응답 크기200
요청·외부 서버 처리시간과 외부 서버 상태 코드

①과 달리 파일에 기록되며, 메모리에서 2분에 사라지는 값이 아닙니다.

  • 앱 API의 HTTP·HTTPS와 알 수 없는 Host의 접속 로그 모두 요청 경로·질의 문자열·Host·접속 프로그램 정보(User-Agent)를 기록하지 않습니다.
  • 서버 앞단의 요청 처리 오류 로그는 요청 주소를 부분적으로 제외할 수 없어 파일에 저장하지 않습니다. 상태 코드와 외부 서버 상태·처리시간은 위 접속 기록에 남기고, 서버 프로그램 오류는 개인정보 원문이 없는 오류 코드와 추적번호로 확인합니다.
  • 접속 파일 로그는 14일 보관 후 정기 삭제합니다. 매일 회전하고 회전본의 보관 개수와 기간을 제한합니다.
  • 앱·백엔드가 작성하는 서비스 로그에는 로그인 정보·토큰·인증 코드·요청·응답 본문과 예외 원문을 남기지 않습니다.
  • 회원 정보와 연결해 보관하지 않으며, 추천·검색·개인화에 쓰지 않습니다.

위치 정보 — 기기 위치를 수집하지 않습니다

앱은 위치 권한을 요청하지 않습니다. 지금 어디에 있는지를 자동으로 알아내지 않고, 이동한 경로를 기록하지도 않습니다.

좌표가 쓰이는 두 자리

좌표는 쓰이는 자리가 둘이고, 남는 기간이 서로 다릅니다.

① 주변을 찾을 때 쓰는 좌표 — 회원 정보와 연결하지 않고, 5분 뒤 사라집니다.

  • 추천 처리에서는 회원 데이터로 저장하지 않습니다. 앱·백엔드가 작성하는 서비스 기록과 서버 앞단 접속·요청 처리 오류 로그에도 남기지 않습니다.
  • 다만 서버 메모리에 5분간 둡니다. 같은 자리를 다시 찾을 때 외부 서비스에 같은 질문을 반복하지 않기 위한 것으로, 5분이 지나면 더는 사용되지 않으며 이후 메모리 정리 시점에 지워집니다.
  • 누가 요청했는지는 함께 두지 않습니다. 회원번호·이메일·로그인 토큰을 이 값과 묶지 않으므로, 남아 있는 동안에도 어떤 이용자가 찾은 곳인지 알 수 없습니다.

② 직접 저장한 것의 좌표 — 회원 정보로 보관합니다.

이용자가 [저장]을 누른 경우에만 좌표가 회원 데이터로 남습니다. 저장하는 것이 두 가지라 남는 좌표도 두 가지입니다.

저장한 것남는 좌표
러닝코스출발 지점 좌표, 경로 좌표
여행 동선동선에 담긴 장소 블록의 좌표, 고른 숙소의 좌표

여행 동선은 일정·장소 이름만이 아니라 그 장소들이 어디인지도 함께 저장합니다. 저장한 동선을 다시 불러와 지도에 그리기 위한 것입니다.

  • 저장한 코스나 동선을 삭제하면 함께 삭제됩니다.
  • 회원 탈퇴 시 삭제됩니다.

즉 ①은 찾는 동안에만 사용되고 ②만 남습니다. [저장]을 누르지 않으면 좌표는 회원 정보로 보관되지 않습니다.

자동으로 수집하지 않는 것 — 광고 식별자, 연락처, 사진, 통화 기록, 기기에 설치된 앱 목록은 수집하지 않습니다.

3. 개인정보의 처리 및 보유 기간

회원 탈퇴 시 운영 데이터베이스에서 지체 없이 파기합니다. 계정과 함께 찜·여행 동선· 러닝코스·동의 이력이 모두 삭제되며, 기기에 남아 있던 사본도 지웁니다.

항목보유 기간
회원 정보와 저장한 내용탈퇴 시 삭제

7. 개인정보의 파기 절차 및 방법

운영팀은 개인정보의 보유 기간이 지나거나 처리 목적이 달성되면 지체 없이 해당 개인정보를 파기합니다.

파기 절차

  • 회원 탈퇴 요청을 받으면 본인 확인 후 운영 데이터베이스에서 계정과 관련 데이터를 즉시 삭제합니다.
  • 보유 기간이 정해진 기록(인증 기록, 로그인 유지 토큰 등)은 만료 시각을 기준으로 정기 정리 작업이 삭제합니다.
  • 법령에 따라 보존해야 하는 정보는 다른 개인정보와 분리해 보관한 뒤, 보존 기간이 끝나면 파기합니다.

파기 방법

  • 전자적 파일 형태의 정보는 복구할 수 없는 방법으로 삭제합니다.
  • 서버 메모리에만 두는 값(요청 횟수 계산용 IP 주소, 주변 검색 좌표)은 만료 후 메모리에서 제거됩니다.

백업에 남은 탈퇴 데이터

  • 운영 데이터베이스는 매일 암호화해 백업하며 최대 7일 보관한 뒤 자동 삭제합니다.
  • 백업에는 인프라 운영책임자만 접근할 수 있습니다.
  • 백업을 복원하는 경우 탈퇴 이후의 삭제 내역과 만료 기록 정리를 다시 반영합니다.
  • 그 결과를 확인하기 전에는 복원된 서비스를 외부에 공개하지 않습니다.

9. 개인정보의 안전성 확보 조치

기술적 조치

  • 비밀번호는 되돌릴 수 없는 해시로만 저장합니다.
  • 앱과 서버 사이의 통신은 암호화(HTTPS)합니다.
  • 앱과 서버는 비밀번호·토큰·인증 코드·이메일 주소·이용자 좌표를 로그에 남기지 않습니다 — 저희가 짠 코드에서 보장하는 범위입니다.
  • 서버 앞단의 HTTP·HTTPS·알 수 없는 Host 접속 로그에는 요청 경로·질의 문자열·Host·접속 프로그램 정보를 남기지 않습니다. 요청 원문을 부분적으로 제외할 수 없는 앞단 오류 로그는 파일에 저장하지 않고, 최소 접속 기록과 서버 오류 코드·추적번호로 장애를 확인합니다.
  • 비밀키는 서버에만 둡니다. 뜯어내면 남이 대신 호출할 수 있는 키(한국관광공사·카카오 REST)는 앱에 넣지 않습니다. 앱에 들어가는 것은 카카오 네이티브 앱 키 하나이며, 이 키는 앱에 넣도록 설계된 공개 식별자이고 등록된 앱 서명에서만 동작합니다.
  • 운영 데이터베이스 백업은 암호화하고 접근 권한을 인프라 운영책임자로 제한합니다.
  • 비밀번호를 변경하면 로그인 유지 토큰을 모두 폐기합니다.

관리적 조치

  • 운영 서버·데이터베이스·백업 접근 권한을 업무상 필요한 최소 인원으로 제한합니다.
  • 운영 계정과 비밀정보를 용도별로 구분하고 저장소와 분리해 관리합니다.
  • 장애·침해사고 대응과 백업·복구 절차를 문서화하고 복원 결과를 검증합니다.
  • 담당자나 업무가 변경되면 불필요한 접근 권한을 회수합니다.
  • 개인정보가 로그나 저장소에 포함되지 않도록 운영 절차를 점검합니다.

물리적 조치

운영팀은 자체 전산실을 운영하지 않고 AWS 데이터센터를 이용합니다. 데이터센터의 출입통제와 시설 보호는 AWS의 물리적 보안통제에 따르며, 운영팀은 서버와 백업에 대한 논리적 접근 권한을 최소화합니다.

10. 자동 수집 장치의 설치·운영 및 거부

서비스는 쿠키를 비롯한 개인정보 자동 수집 장치를 사용하지 않습니다. 앱은 광고 식별자를 수집하지 않으며, 이용자의 행동을 추적하는 분석 도구나 제3자 광고 SDK를 사용하지 않습니다.

로그인 상태를 유지하기 위한 토큰은 이용자의 기기 안에만 저장되며, 로그아웃하거나 앱을 삭제하면 함께 지워집니다.

다만 서버는 요청을 받을 때 접속 기록(IP 주소·시각·허용된 요청 방식·상태 코드·처리시간 등)을 남깁니다. 이는 이용자의 기기에 무엇을 설치해 수집하는 것이 아니라 서버가 자체적으로 남기는 운영 기록이며, 자세한 내용은 2. 처리하는 개인정보의 항목에 적었습니다.
